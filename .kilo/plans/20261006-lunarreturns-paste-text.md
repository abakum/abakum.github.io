# LunarReturns: вставка из буфера — текст в дополнение к JSON

## Контекст

- `LunarReturns/index.html`: кнопка «📋» (`pasteDb`, index.html:2575) читает буфер через `navigator.clipboard.readText` (или диалог `#pasteFallbackArea`, index.html:613) и вызывает `importDbText` (index.html:2585), которая принимает только JSON-массив записей `{n, d[, h, m]}`.
- `/home/koka/src/LunarReturns/lunarreturns.js:468-532` — эталонный разбор строк-триггеров: `explicitZoneMinutes`, `TRIGGER_RE`, `parseTrigger`. Формат: `Имя 19630927`, `Имя 1963-09-27 14:30`, `Имя 12:30 (МСК+2)`, `Имя 12:30 (Пермь)`, `Имя 12:30 UTC+5`. Результат — запись в МСК `{n, d[, h, m]}`.
- В `index.html` уже есть `ZONE_EPOCHS`, `CITY_ZONE`, `cityDiffMin` (index.html:744-751); отсутствуют `CITY_INDEX`, `explicitZoneMinutes`, `TRIGGER_RE`, `parseTrigger`.
- Решение пользователя: нераспознанные строки при разборе текста молча пропускать (как бот пропускает не-триггеры).

## Изменения (только `LunarReturns/index.html`)

1. **Перенести разбор из lunarreturns.js** (после `cityDiffMin`, ~строка 751), адаптировав:
   - `CITY_INDEX` (нижний регистр → каноническое имя города);
   - `explicitZoneMinutes` (lunarreturns.js:469);
   - `TRIGGER_RE` (lunarreturns.js:477) и `parseTrigger` (lunarreturns.js:479) — с adaptations: ошибки разбора возвращают `null` (молчаливый пропуск); из `TRIGGER_RE` убраны `\b` вокруг группы зоны — в юникод-режиме `\b` ASCII-only, и «МСК+2» без скобок не матчилось даже в боте (только `(МСК+2)` и `UTC+5`).
2. **`importDbText` (index.html:2585)**: если `JSON.parse` упал ИЛИ распарсился не массив/не все записи валидны — попробовать текстовый разбор:
   - `text.split(/\s*\n+\s*/).filter(Boolean)`, каждую строку через `parseTrigger`;
   - строки с `null` или `error` — молча пропускать;
   - собранные `rec` прогнать через `validRecord` (страховка) и импортировать по существующей логике (вопрос «добавить/заменить», дедупликация, `saveDb`, рендер);
    - если не распознано ни одной строки — `status("В буфере нет списка событий", true)`;
   - JSON-путь оставить первым: валидный JSON-массив по-прежнему импортируется как раньше. Уточнение: если JSON распарсился, но невалиден (не массив/записи), тоже падаем на текстовый разбор — текст мог быть заклеймён скобками.
3. **Плейсхолдер** `#pasteFallbackArea` (index.html:613) — по формулировке пользователя, с указанием источников (кнопки тулбара index.html:601-603) и нескольких примеров текстового формата (все варианты из `parseTrigger`):
   `placeholder="Вставьте JSON списка событий (кнопка ⎘ «Скопировать список событий» или скан QR-кода кнопки ⛶) либо строки вида: «Ада 18151210», «Ада 1815-12-10 14:30», «Ада 1815-12-10 12:30 (Пермь)», «Ада 1815-12-10 12:30 МСК+2»"`.
   Разнообразие примеров покрывает: дату без разделителей, дату со временем, время с городом в скобках, явный сдвиг зоны МСК+N/UTC+N.
4. Обновить `title`/`aria-label` кнопки «📋» (index.html:601): упомянуть, что принимается JSON или строки вида «Ада 18151210», «Ада 1815-12-10 14:30», «Ада 1815-12-10 12:30 (Пермь)», «Ада 1815-12-10 12:30 МСК+2».

## Валидация

- В браузере открыть `LunarReturns/index.html`:
  - вставить JSON `[{"n":"Ада","d":"1963-09-27"}]` — импорт как раньше;
  - вставить текст `Ада 19630927\nАда Лавлейс 1815-12-10 14:30 (Пермь)\nмусорная строка` — 2 записи импортированы, мусор молча пропущен; проверить пересчёт зоны Пермь → МСК;
  - вставить мусор целиком — статус «В буфере нет списка событий»;
  - проверить плейсхолдер (упоминает кнопки ⎘ и ⛶, 4 примера текстового формата) и подсказку кнопки.
