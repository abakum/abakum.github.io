# Plan: Перенос базы между версиями VK-хостинга + отказ от isAllowedUrl-редиректа

## Цель
При смене версии VK-хостинга (новый stage-URL = новый origin = пустой localStorage):
1. **Основной путь** — автоматический перенос базы со старого origin: указатель
   версий в `VKWebAppStorage` (URL — не ПДн) + цепочка навигаций с базой в
   `#`-фрагменте. ПДн не покидают устройство.
2. **Фолбэк при провале миграции** — ручной: приложение показывает ссылки на
   старые URL и инструкцию «⎘ скопировать там → 📋 вставить здесь». Для этого
   **удаляем isAllowedUrl-редирект** — старые stage-URL должны открываться напрямую.

## Решение об откате редиректа
Редирект (план 20260901-vk-dev-url-redirect-plan.md) защищал stage-URL, которые
публиковались в CI. С тех пор: (а) CI маскирует stage-URL (deploy-lunarreturns-vk.yml),
(б) фолбэку миграции нужен прямой заход на старый URL без `vk_app_id`.
Ущерб от открытия stage-URL напрямую минимален: база — локальная для устройства,
VK-хранилище вне VK всё равно недоступно (`vkminiapp` false), приложение не
опубликовано. Редирект удаляем целиком.

## Изменения — `LunarReturns/index.html`

### 1. Удалить редирект (index.html:230-242)
Убрать блок: комментарий, `VK_APP_URL`, `PWA_PREFIX`, `isAllowedUrl()` и вызов
`if (!isAllowedUrl()) location.replace(...)`. Больше ничего на них не ссылается
(проверено поиском). Уведомить в README, что поведение изменено.

### 2. Указатель версий в VKWebAppStorage (не ПДн — без чекбокса согласия)
- Ключи: `lr_origin_<unixtime>` — дата появления версии в имени ключа
  (записывается при первом старте на этом origin). Перечисление доступно:
  `VKWebAppStorageGetKeys` (уже используется в `vkDbPut`, index.html:1444).
- `vkPointerPut()` при старте в VK-контексте и после каждого `saveDb()`:
  если ключ с текущим origin уже есть — не трогать; иначе записать новый.
  Значение — только `location.origin` (дата уже в ключе, кортеж не нужен).
- `vkPointerGet()`: `vkStorageGetKeys()` → фильтр по префиксу `lr_origin_` →
  прочитать значения (`vkStorageGet`) → сортировка по дате (ключу) по убыванию.
- Ограничение истории: хранить последние 10; более старые затирать пустой
  строкой (удаления ключей в VKWebAppStorage нет — как в `vkDbPut`).

### 3. Автоматическая миграция (цепочка location.replace, без iframe)
- **Приём**: в начале init (VK-контекст), до `loadDb`: hash `#lr_db=<json>` →
  `JSON.parse` + фильтр `validRecord` → `localStorage.setItem(DB_KEY, …)` →
  очистить hash (`history.replaceState`) → статус «База перенесена со старой
  версии»; hash `#lr_fail=1` → миграцию не повторять, перейти к фолбэку (п. 4).
- **Запуск** `maybeMigrateDb()` в init, если после `loadDb` база пуста/только
  сид «Ада»: первый непробованный origin из списка указателей (по дате, свежие
  сначала) ≠ текущему →
  `location.replace(old + pathname + search + "#lr_migrate=" + enc(returnUrl))`,
  где returnUrl = текущие origin+pathname+search (launch-параметры VK
  сохраняются — иначе сломается `vkminiapp`).
- **Отдача** (код того же приложения на старом origin): hash `#lr_migrate=…` в
  начале init: валидировать returnUrl (https + `.pages.vk-apps.ru` + pathname
  тот же — защита от open redirect); есть база → `location.replace(returnUrl +
  "#lr_db=" + enc(JSON))`; нет → `returnUrl + "#lr_fail=1"`; в этом режиме
  приложение не рендерить.
- Защита от петель: счётчик попыток в hash (`&lr_try=N`), максимум 3.

### 4. Фолбэк: ссылки + инструкция (замена буферной механики — отклонена)
- Если миграция не удалась (`#lr_fail`, исчерпаны попытки, указателей нет, но
  база пуста) — панель под статусом:
  - заголовок «Не удалось перенести базу автоматически»;
  - ссылки на все прежние origin'ы с датами версий (из ключей `lr_origin_<дата>`;
    открываются напрямую — редиректа больше нет);
  - инструкция: «Откройте прежнюю версию → ⎘ (скопировать) → вернитесь → 📋
    (вставить)».
- Кнопки ⎘/📋/⛶ уже есть и всегда видимы. Буфер обмена приложение не трогает.

## Сценарии проверки
1. Новый пользователь: указателей нет → нет миграции, сид «Ада».
2. Обновление версии: пустой origin → цепочка `#lr_migrate` → `#lr_db` → база
   на месте, hash очищен, записан новый указатель `lr_origin_<дата>`.
3. Старый origin мёртв (404): попытки исчерпаны → фолбэк-панель со ссылками
  (с датами версий) и инструкцией; ссылки ведут на старые версии, ⎘/📋
  работают (редиректа нет).
4. Вне VK (прямой заход на stage-URL в браузере): приложение работает, база —
  локальная для этого браузера, VK-функции отключены (`vkminiapp` false).
5. Отказ ПДн: ключи "0".."999" в VKWebAppStorage не пишутся, только `lr_origin_*`.
6. Десктоп (iframe vk.ru) и мобильный клиент (webview top-level) — миграция
   проходит в обоих (каждая страница читает своё first-party хранилище).
7. 11-я версия: самый старый указатель затёрт пустой строкой (история ≤ 10).

## Валидация
- vm-песочница: разбор `#lr_db`/`#lr_migrate`, валидация returnUrl, запись/чтение
  указателей `lr_origin_<unixtime>` (перечисление + фильтр + сортировка + затирание
  старше 10), счётчик попыток; `isAllowedUrl`-блок удалён без остаточных ссылок.
- Два подряд dev-деплоя: после второго база переносится автоматически; при
  «убитом» origin — фолбэк-панель работает.

## Отклонённые альтернативы
- Буфер обмена (автокопирование и «копировать перед форвардингом») — требуется
  transient activation (тап), clipboard-write в iframe может быть запрещён;
  «лекарство хуже болезни» (решение пользователя).
- iframe + postMessage — партиционирование стореджа на мобильных (webview,
  top-level) даёт пустой localStorage у iframe старого origin.
- `document.domain` — отключён в современных Chromium (origin-keyed agent
  clusters), заголовок на хостинге VK не поставить; «главный» сабдомен удаляется
  VK по лимитам версий.
- Cookie `Domain=.pages.vk-apps.ru` — ПДн читаемы любым мини-аппом на `*.vk-apps.ru`.

## Риски
- Первый переход (текущие задеплоенные версии без кода миграции) — вручную
  через фолбэк-инструкцию (⎘ на старой версии → 📋 на новой).
- webview/iframe-политики VK могут мешать навигациям — тогда работает ручной
  фолбэк; деградация мягкая.
- Прямой доступ к stage-URL теперь без редиректа — приемлемо: CI маскирует URL,
  вне VK база привязана к устройству/браузеру, VK-хранилище недоступно.
- Адрес версии в облаке — не ПДн (не идентифицирует лицо); тексты согласия
  не меняются (решение пользователя).
