# Миграция localStorage-настроек между версиями ВК-хостинга (lr_ls)

## Контекст

При каждой выкладке мини-апп ВК получает новый origin с пустым localStorage. Сейчас автоматическая миграция (через `#`-фрагмент URL, ПДн не покидают устройство) переносит **только базу** (`#lr_db`, index.html:279-295); отдающая сторона — `lr_migrate`-ветка (index.html:260-278), указатели версий — `vkPointerPut` в `VKWebAppStorage`. Остальные localStorage-ключи теряются:

| Ключ | Смысл | Последствие потери |
|---|---|---|
| `lunarreturns.days` (`DAYS_KEY`) | выбранный религиозный календарь | сбрасывается настройка |
| `lunarreturns.pdConsent` | согласие на ПДн базы | сбрасывается чекбокс |
| `lunarreturns.pdPushConsent` | push-согласие | сбрасывается чекбокс |
| `lunarreturns.vkpush` (`VKPUSH_KEY`) | флаг активной пуш-подписки | 🔔 «выключен», хотя серверная подписка по `vk_user_id` жива |
| `lunarreturns.autotap` (`AUTOTAP_KEY`) | флаг «автотап уже был сегодня» | двойной автотап в день смены версии |

Город (`fCity`) — селект формы записи, в localStorage не хранится, не участвует. `lr_origin_*` указатели и так в `VKWebAppStorage`.

## Решения (зафиксировано с пользователем)

1. **Механизм**: рядом с `#lr_db` отдающая версия дописывает в возвращаемый hash параметр **`lr_ls`** — маленький JSON белого списка ключей со значениями. Без дублирования базы; старые версии кода `lr_ls` игнорируют (они читают только `lr_db`).
2. **Бутстрап-ограничение** (как у `lr_db`): отдающая сторона — предыдущая версия кода, поэтому полный перенос заработает со второй смены версии после выката; первый переход принесёт только базу — деградация к текущему поведению.
3. **ПДн**: значения `lr_ls` (календарь, флаги согласия, дата автотапа) — не ПДн; hash-фрагмент устройства не покидает. Новый чекбокс согласия не нужен.
4. **`lr_fail`-ветка**: `lr_ls` прикладывается и к ней — настройки переносятся даже когда базы на старой версии не было.
5. **Не затирать существующее**: ключ применяется только если его ещё нет на новом origin. Невалидные значения молча пропускаются.

## Задачи (клиент, `abakum.github.io/LunarReturns/index.html`)

1. **Белый список**: `const LR_LS_KEYS = [DAYS_KEY, PD_CONSENT_KEY, PD_PUSH_CONSENT_KEY, VKPUSH_KEY, AUTOTAP_KEY];` — в блок констант (~index.html:201-212), где эти ключи уже объявлены.
2. **Отдающая сторона** (`lr_migrate`-ветка, index.html:260-278): после формирования `back.hash` (`lr_db=…` или `lr_fail=1`) собрать `ls = {ключ: значение}` для существующих в localStorage ключей белого списка; если объект непуст — дописать `&lr_ls=` + `encodeURIComponent(JSON.stringify(ls))`.
3. **Принимающая сторона** — хелпер `applyLsParams(p)` и вызовы в `lr_db`- и `lr_fail`-ветках (до основного init: `loadDayKind()`/`initPdConsent()`/`initPushConsent()`/`refreshPushBtn()` читают localStorage после):
   - только ключи из белого списка, только отсутствующие в localStorage;
   - валидация: `DAYS_KEY` — строка и `DAYS_DEFS[v]` существует (легаси-формат `[...]` не переносить); `PD_CONSENT_KEY`/`PD_PUSH_CONSENT_KEY`/`VKPUSH_KEY` — значение `=== "1"`; `AUTOTAP_KEY` — `/^\d{4}-\d{2}-\d{2}$/`;
   - ошибки разбора — тихий пропуск всего `lr_ls` (try/catch).
4. **README (страницы-репо)**, раздел «Перенос локальной базы между версиями»: дописать про `lr_ls` (что переносится, первый переход после выката — только база, значения не ПДн).
5. ~~**Лимит записей в VKWebAppStorage: 989 → 984**~~ — **отменено пользователем**: мигрируемые через `lr_ls` переменные лежат в localStorage и VK-хранилище не занимают; лимит остаётся 989/990.

## Валидация

- Имитация вручную: `location.replace(originB + pathname + search + "#lr_db=<enc>&lr_ls=<enc {days:'orthodox',pdConsent:'1',pdPushConsent:'1',vkpush:'1',autotap:'2026-09-02'}>")` → на B: база перенесена, dayKind применён, чекбоксы взведены, 🔔 активен, повторного автотапа нет.
- Только `lr_db` (старый формат) → работает как раньше, ls-ключи не трогаются.
- `lr_fail=1&lr_ls=…` → настройки применены, логика попыток миграции/фолбэк не сломаны.
- Уже существующие на B ключи не перезаписываются; невалидные значения (`days:'xxx'`, `autotap:'abc'`) пропускаются.
- Регресс: `#N`, OAuth-хэши, миграционные попытки/фолбэк — hash очищается как раньше. Синтаксис инлайн-JS — `node`-проверкой (`new Function`).
- Лимит: без изменений (989/990) — пункт отменён, см. задачи п.5.

## Вне scope

- Ручной перенос ⎘/📋 (копирование базы текстом) — остаётся только для базы.
- Перенос `sessionStorage` (`lr_migrate_attempts`, `lr_migrate_tried`) — сознательно нет: попытки считаются на новом origin.
