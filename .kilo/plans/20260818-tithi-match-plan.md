# Lunar Returns: переход на титхи (лунные дни) как критерий совпадения

Файл: `LunarReturns/index.html` (единственный изменяемый файл).

## Решения (подтверждено пользователем)

1. **Критерий совпадения** — точное равенство номера титхи (лунного дня) в годовщину номеру титхи рождения. Текущий `phaseMatch` (окно ±1/16 цикла) удаляется. Это выравнивает число «удачных» годов у всех людей независимо от положения внутри метонова цикла.
2. **Определение титхи** — как в Джйотиш: интервал 12° эклиптического удлинения Луна–Солнце. Номер = `floor(elongation/12°) + 1`, 1..30. Удлинение уже есть в `moonNew`: `elongation = fixangle(moonAge)`, `m.phase = elongation/360`, значит `tithi = floor(m.phase*30)+1`.
3. **Расчётное время рождения** — середина лунного дня рождения: момент, когда удлинение = `(n − 0.5) · 12°`. От него считаются «точные» фаза луны и созвездие луны для отображения (устраняет дрейф на границах: у людей с одинаковой титхи — одинаковые отображаемые фаза и знак).
4. **Отображение** — имя титхи выводится однократно, в «легенде» (шапке результата) как хэштег: `#пратипада` … `#пурнима`. В строках «удачных» годов при совпадении титхи показывается иконка точной фазы (вычисленной по середине титхи).

## Изменения по коду

### 1. Номер и имя титхи

```js
const tithiInt = m => Math.floor(m.phase * 30) + 1;          // 1..30
const TITHI_BASE = ["пратипада","двитья","трития","чатуртхи","панчами","шаштхи",
  "саптами","аштами","навами","дашами","экадаши","двадаши","трайодаши","чатурдаши"];
const tithiName = n => n === 15 ? "пурнима" : n === 30 ? "амавасья"
  : TITHI_BASE[(n - 1) % 15];
```

(уточнить написание «трития/тритья» — в индологии обычно «трития».)

### 2. Середина титхи — расчётное время

Функция `tithiMid(t, n)`: бисекция по времени вокруг `t` (±1 суток), ищем момент, когда `moonNew(t')​.phase*30` проходит значение `n − 0.5`. `moonNew` монотонна на суточном интервале с запасом (фаза растёт ~1/29.5 в сутки; колебания поправок малы). Итераций ~40 при точности 1 с.

```js
function tithiMid(t, n) {
    const target = n - 0.5;                    // в единицах фазы *30
    let lo = new Date(t.getTime() - 86400000);
    let hi = new Date(t.getTime() + 86400000);
    const f = d => moonNew(d).phase * 30 - target;
    // учесть переход через 30→1: если f(lo) и f(hi) одного знака из-за wrap,
    // сдвинуть окно; otherwise обычная бисекция
    for (let i = 0; i < 40; i++) {
        const mid = new Date((lo.getTime() + hi.getTime()) / 2);
        if (f(mid) < 0) lo = mid; else hi = mid;
    }
    return new Date((lo.getTime() + hi.getTime()) / 2);
}
```

Обработка wrap (титхи 1, середина ~0.5): фазу привести к непрерывной: `x = phase*30; if (x < target - 15) x += 30;`.

### 3. Канонические фаза и знак для родившегося

В `la(t)`:
- `m0 = moonNew(t)`; `n0 = tithiInt(m0)`.
- `tm = tithiMid(t, n0)`; `mMid = moonNew(tm)`.
- `p0 = phaseName(mMid, …)` и `z0 = moonZodiacName(mMid, …)` — берутся из середины титхи (точные, стабильные).
- Строка легенды: имя титхи с хэштегом однократно, напр. `🕘 #пурнима` (иконку можно опустить, просто `#пурнима`). Имена — только в этой строке шапки.

### 4. Совпадение в году

В цикле по годам `m = moonNew(bd)`; совпадение титхи: `tithiInt(m) === n0` (заменяет `phaseMatch(m0, m)`; `PHASE_MATCH_W` и `phaseMatch` удалить). При совпадении показывается `p0` — иконка точной фазы середины титхи (одинаковая у всех с этой титхи).

### 5. Очистка

- Удалить `PHASE_MATCH_W`, `phaseMatch`.
- `PHASE_POINT_W`, `phaseInt`, `phaseName` остаются — используются для вывода иконки фазы по `mMid`.

## Проверка

- Нет сборки/тестов; проверка вручную в браузере:
  - Ада `1815-12-10` (без времени → 12:00): в шапке — титхи-хэштег, фаза и знак из середины титхи; знаки не «прыгают» при сдвиге времени рождения на часы внутри одного лунного дня.
  - Две записи с датами в пределах одного лунного дня, но разным временем — идентичные p0/z0/титхи.
  - В годах: совпадения титхи равномерны (~1 раз в ~2.7 года: 365.24/ (12/360·29.53·… ) — фактически ~ каждый 2–3 года), без кластеров у «неудачных» фаз.
  - Синтаксис: `node --check` невозможен (inline-скрипт) — вынести проверку копированием или открыть страницу и убедиться в отсутствии ошибок консоли.
- QR и размер текста: длина строки годов не меняется (иконка фазы на месте), шапка +1 строка — проверить, что QR помещается (`QR_MAX_BYTES`).
