# Lunar Returns: реальная фаза вместо равных вёдер

Файл: `LunarReturns/index.html`. План-файл: этот же документ (бывший 1787049530064 переименован в 20260818).

## Контекст

Совпадение считается только по номеру титхи (`tithiInt(m) === n0`); `phaseInt` используется чисто для отображения. Фаза отображается от середины титхи, где удлинение всегда ровно `(n−0.5)·12°`, поэтому иконка фазы — детерминированная функция номера титхи. Равные вёдра 1/8 (план 20260817) больше ничем не оправданы и вводят в заблуждение: мама (титхи 18, удлинение 210°, 2.5 суток после полнолуния) получает 🌕 «полнолуние».

Решение пользователя: честная схема по титхи — 🌕 только пурнима (титхи 15), 🌑 амавасья/пратипада (30 и 1), четверти — по паре титхи у 90°/270°.

## Изменения

1. Заменить `phaseInt(m)`/`PHASE_*`-вёдра на таблицу титхи→фаза:

```js
// индекс фазы для титхи 1..30: 🌑🌒🌓🌔🌕🌖🌗🌘
const TITHI_PHASE = [0,1,1,1,1,1,2,2,3,3,3,3,3,3,4,5,5,5,5,5,5,6,6,7,7,7,7,7,7,0];
const PHASE_ICON = ["🌑","🌒","🌓","🌔","🌕","🌖","🌗","🌘"];
const PHASE_RU = ["Новолуние","Молодая луна","Первая четверть","Прибывающая луна","Полнолуние","Убывающая луна","Последняя четверть","Старая луна"];
const phaseName = (n, ru) => (ru ? PHASE_RU : PHASE_ICON)[TITHI_PHASE[n - 1]];
```

Распределение (центр удлинения титхи = (n−0.5)·12°):
- 🌑 новолуние: 1 (6°), 30 (354°)
- 🌒 молодая: 2–6 (18–66°)
- 🌓 первая четверть: 7–8 (78°, 90°)
- 🌔 прибывающая: 9–14 (102–162°)
- 🌕 полнолуние: 15 (174°; пурнима)
- 🌖 убывающая: 16–21 (186–246°)
- 🌗 последняя четверть: 22–23 (258°, 270°)
- 🌘 старая: 24–29 (282–342°)

Симметрично: 2+5+2+6+1+6+2+6 = 30.

2. В `la()` заменить вызовы `phaseName(mMid, …)` на `phaseName(n0, …)` (строки ~258, ~273). Удалить старый `phaseInt`. В строках годов `p = p0` — без изменений (рождественская иконка при титхи-совпадении).
