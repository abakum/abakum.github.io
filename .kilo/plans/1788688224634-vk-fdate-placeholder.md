# План: оверлей «Дата» скрывать только в нативных клиентах VK (vk_platform android/iphone)

## Решение (по итогам деплоя)
Итоги проверки после деплоя:
- **GitHub Pages (PWA)** — ок, оверлей «Дата» виден.
- **vk.apk (webview, `vk_platform=android`)** — ок, оверлей скрыт, нативный плейсхолдер контрастный.
- **m.vk.ru/app... (мобильный браузер, `vk_platform=mobile_web`)** — беда: оверлей скрыт, а нативный плейсхолдер НЕ контрастный → поле «Дата» выглядит пустым.

Вывод: скрывать оверлей надо только в нативных клиентах VK (`android`/`iphone`), а в `mobile_web` оставить оверлей (как вне VK).

## Режимы (важно не путать)
- **GitHub Pages (PWA)**: страница в обычном браузере, без `vk_app_id` → `.vk` не ставится. Здесь всё работает, не трогаем.
- **Хостинг VK (мини-апп), мобильный**: тот же `index.html` (сборка `build/`, `scripts/copy-build.js`) на origin VK. VK-клиент при запуске мини-аппа дописывает `vk_app_id` в URL → `vkminiapp` (index.html:571) → класс `.vk` на `<html>` (index.html:575). В этом режиме пользователь видит баг.
- **Хостинг VK (мини-апп), десктоп Chrome (`vk.ru/app54746591`)**: launch-параметры подставляет веб-сервер VK, встраивая мини-апп в iframe с `vk_app_id` в URL. `vkminiapp`/`.vk` срабатывают и здесь, но бага нет: медиазапрос `(hover: none) and (pointer: coarse)` не выполняется, оверлей скрыт (`display:none`, index.html:213), работает нативный плейсхолдер.

Детекция «VK вообще» уже есть (`vk_app_id` → `.vk`); для нового фиксa добавляется только синхронное различение `mobile_web` (см. Изменения, п. 1).

### Как отличить десктопный Chrome (`vk.ru/app...`) от webview VK-приложения
Если когда-нибудь понадобится программное различение (для этого фиксa НЕ требуется):
1. `vkBridge.send("VKWebAppGetLaunchParams")` → `vk_platform`: `"desktop_web"` в десктопном браузере, `"android"`/`"iphone"` в приложении VK. Официальный способ, vk-bridge уже подключён.
2. `navigator.userAgent`: webview приложения содержит `Android` + `; wv)` (часто `VKMobileApp`); десктопный Chrome — нет.
3. Косвенно: медиазапрос `(hover: none) and (pointer: coarse)` — истина в мобильном webview, ложь на десктопе.

## Проблема
Оверлей «Дата» (`#fDatePh`, index.html:415) — HTML-текст поверх пустого `<input type="date">`, включается медиазапросом `@media (hover: none) and (pointer: coarse)` (`opacity:.72`, подложка `var(--surface)`, index.html:220-232). Текущее правило `html.vk #fDatePh { display: none; }` (index.html:233-236, добавлено предыдущим фиксaм) скрывает оверлей во всём VK-режиме, включая `mobile_web` — а там UA-плейсхолдер не контрастный, поле выглядит пустым. Нативный плейсхолдер контрастен только в webview нативных приложений VK (`vk_platform=android`/`iphone`); правило надо сузить до них.

## Изменения (один файл `LunarReturns/index.html`)

1. **Head, до `<style>` и до первого кадра.** Классы `.vk`/`.vk-mweb` нужно ставить синхронно в head — иначе при reload в vk.apk первый кадр отрисовывается без `.vk`, и оверлей «Дата» промелькивает (та же проблема «промелькивания», что уже решена для темы ранним скриптом index.html:25-49; комментарий там это прямо описывает). Расширить существующий head-скрипт темы (index.html:25-49) тем же `URLSearchParams`, который он уже создаёт для `appearance`:

В IIFE (index.html:26-48), после создания `var q = new URLSearchParams(location.search);` (сейчас `q` объявлен внутри ветки темы — вынести создание `q` на верх IIFE, ветке оставить `q.get(...)`), добавить перед концом IIFE:

```js
// Ранние классы VK: до первого кадра, чтобы оверлей «Дата» не промелькивал
// при reload в нативных клиентах ВК (см. html.vk:not(.vk-mweb) ниже).
if (q.has("vk_app_id")) {
    root.classList.add("vk");
    if (q.get("vk_platform") === "mobile_web") root.classList.add("vk-mweb");
}
```

Здесь `var q` уже нужен скрипту темы; в ветке, где `q` объявлялся локально (index.html:32), объявление убрать, использовать общий. `root` уже есть (index.html:41) — но классы VK ставить до/независимо от веток темы; порядок не важен, `root` объявлен до использования, если вставить блок после строки 43.

Синхронная детекция `mobile_web` по URL — так же, как это делает vk-bridge (vendor/vk-bridge.min.js:1, регэксп по `location.search`); асинхронный `VKWebAppGetLaunchParams` не нужен.

2. **Конец body (index.html:573-579).** Убрать позднюю установку `if (vkminiapp) document.documentElement.classList.add("vk");` (дубль, теперь в head). Константу `vkminiapp` оставить — она используется остальной логикой (vkBridge, PTR, push).

3. **CSS, текущее правило (index.html:233-236) сузить:**

```css
/* В webview нативных приложений ВК (android/iphone) нативный плейсхолдер
   дейт-инпута виден и контрастен — оверлей «Дата» там не нужен (иначе
   текст двоится). В mobile_web (мини-апп в мобильном браузере) плейсхолдер
   не контрастный — оверлей оставляем, как вне VK. */
html.vk:not(.vk-mweb) #fDatePh { display: none; }
```

4. **Комментарий над `#fDatePh` (index.html:209-213)** переформулировать: оверлей — для touch-браузеров вне нативных приложений ВК (Android Chrome, mobile_web и т.п.).

## Поведение по режимам после правки
- GitHub Pages / Android Chrome (не VK): оверлей с `opacity:.72` — без изменений.
- vk.apk / iPhone-приложение (`vk_platform=android|iphone`, touch): оверлей скрыт, нативный плейсхолдер — без изменений от прошлого фиксa.
- mobile_web (m.vk.com в мобильном браузере, touch): класс `vk-mweb` → `:not(.vk-mweb)` не срабатывает → оверлей виден снова (полупрозрачный, как вне VK). Подложка `--surface` уже в медиаблоке.
- Десктопный Chrome (`vk.ru/app...`, `desktop_web`): touch-медиазапрос ложен → оверлей скрыт, как и раньше.
- Если `vk_platform` в URL нет (подделка/старые клиенты): `.vk-mweb` не ставится → оверлей скрыт в VK-режиме (поведение прошлого фиксa — безопасный дефолт).

## Риски
- Рефакторинг `q` в IIFE темы: следить, что ветка `appearance`/`vk_theme` (index.html:31-34) продолжает читать тот же `q` — покрыто шагом валидации 5.
- mobile_web на iPhone (Safari в m.vk.com): плейсхолдер Safari не контрастный тоже; оверлей с `--surface` и `opacity:.72` закрывает его, как в Android Chrome — должно быть ок, проверить на iPhone.
- `vk_platform=mobile_web` формально есть и у открывших мини-апп в мобильном браузере, где touch-медиазапрос ложен (редкие гибриды) — тогда оверлей скрыт базовым `display:none`, регресса нет.
- Если `vk_platform` в URL нет (подделка/старые клиенты): `.vk-mweb` не ставится → оверлей скрыт в VK-режиме (безопасный дефолт).

## Что не делаем
- Не трогаем GitHub-режим и Android Chrome: `opacity:.72` остаётся.
- Не используем асинхронный `VKWebAppGetLaunchParams`: синхронного разбора URL достаточно (и он совпадает с логикой vk-bridge), плюс он работает до первого кадра.
- `syncDatePh` (index.html:1294-1298) и правила `#dateWrap.filled` / `:focus-within` не трогаем.
- VK-сборка: `npm run build` копирует index.html как есть (copy-build.js:14-19).

## Валидация
1. DevTools → мобильная эмуляция (touch), `LunarReturns/index.html` без параметров: оверлей «Дата» виден и полупрозрачен (вне VK не задет).
2. То же с `?vk_app_id=1&vk_platform=android`: оверлея нет и не промелькивает при перезагрузке страницы (класс `.vk` в head, до первого кадра).
3. То же с `?vk_app_id=1&vk_platform=mobile_web`: оверлей «Дата» виден и полупрозрачен.
4. `?vk_app_id=1` (desktop-эмуляция, без touch): оверлей скрыт.
5. Тема не сломана: `?vk_app_id=1&appearance=dark` — тёмный первый кадр (IIFE темы после рефакторинга `q` работает).
6. `npm run build` — классы и правило в `build/index.html`.
7. После деплоя в VK: vk.apk — «Дата» не двоится и не промелькивает при reload; m.vk.ru/app54746591 с телефона (Android и iPhone, светлая/тёмная) — «Дата» видна, поле не выглядит пустым; десктоп vk.ru — без регресса.
