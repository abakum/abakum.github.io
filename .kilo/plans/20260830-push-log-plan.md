# План: журнал пушей в LunarReturns (показ под статусом)

## Цель
Service worker при получении push-события пишет протокол (запись в IndexedDB), а страница при открытии показывает этот журнал ниже элемента `#status`. Это нужно для диагностики "сломавшихся" пушей (коммиты 24dd5b2, c1a7fed).

## Файлы
- `LunarReturns/sw.js`
- `LunarReturns/index.html`

## Изменения в sw.js

1. **bump кэша**: `CACHE = "lunarreturns-v5"` (файл меняется — SW должен обновиться).
2. **Добавить функцию `idbPutLog(entry)`**: открыть `indexedDB("lunarreturns", 1)`, store `kv`, прочитать ключ `pushlog` (массив или `[]`), добавить запись в начало, обрезать до 10, `put(JSON.stringify(log), "pushlog")`. Все ошибки — глушить (try/catch / onerror → resolve), журнал не должен ломать показ уведомления.
3. **В обработчике `push`** собирать запись и писать её в любом исходе (до `return`):
   - `t`: время МСК в читаемом виде (`new Date().toLocaleString("ru-RU", { timeZone: "Europe/Moscow" })`),
   - `payload`: `e.data ? e.data.text() : null` (первые ~200 символов),
   - `db`: количество совпадений из `dbLabels` (или `null` при ошибке/нет ключа),
   - `days`: количество из `dayNames` (аналогично),
   - `shown`: `true/false` — было ли показано уведомление.
   
   Реструктурировать async-функцию так, чтобы лог писался через `Promise.all([логика, idbPutLog(entry)])` или запись до ветвления `if (!all.length) return`.
4. **Опционально**: писать запись и в `notificationclick` не нужно — не входит в задачу.

## Изменения в index.html

1. **Разметка**: после `<p id="status">...` добавить `<div id="pushlog" style="display:none;"></div>` + стили (мелкий серый шрифт, `white-space: pre-line`).
2. **Функция `renderPushLog()`**:
   - читать ключ `pushlog` из IndexedDB (по образцу существующего `readKey`-подобного кода в `idbPutDays`, read-only);
   - если массив пуст/нет — скрыть div;
   - иначе показать строки вида `t — payload — db:N days:N shown:yes/no`;
   - добавить кнопку/ссылку «очистить», удаляющую ключ `pushlog` (write tx) и перерисовывающую.
3. **Вызов**: в init-блоке внизу (рядом с `idbPutDays(); refreshPushBtn();`) вызвать `renderPushLog()`.

## Риски / заметки
- SW и страница имеют общее same-origin IndexedDB — доступ подтверждён существующим кодом (`idbPutDb`/`idbPutDays` пишут в тот же store `kv`).
- Параллельное открытие БД из SW и страницы допустимо (версия 1 у обоих).
- `e.data` может отсутствовать (сервер шлёт пустой payload) — логировать `null`, не падать.

## Валидация
- Открыть приложение, убедиться что при отсутствии журнала блок скрыт.
- Отправить тестовый пуш (через функцию или DevTools → Application → Service Workers → Push): убедиться, что в IDB появился ключ `pushlog` и после перезагрузки страницы блок виден под `#status`, включая случай «push без совпадений → shown: false».
- Проверить, что при `!all.length` запись всё равно пишется (это главный диагностический сценарий).
- Кнопка «очистить» удаляет журнал и скрывает блок.
