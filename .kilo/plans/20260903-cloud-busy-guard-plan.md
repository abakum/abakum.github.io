## Дополнение B: месяц и звёзды на подложке PTR

Механика: 🌙 в заголовке (`#titleH1 img`, index.html:208) гаснет **сразу** с началом тяги (класс `ptr-moon`). Большой месяц `icons/icon-192.png` и звёзды постоянно лежат на небе-подложке за формой (`z-index: -1`: после фона `html`, до фона `body`) и открываются, когда PTR сдвигает тело. Видимость — по теме и прогрессу тяги `t = min(dist / THRESHOLD, 1)`:

- **светлая тема:** месяц `opacity: t` (проявляется к порогу), звёзды выключены;
- **тёмная тема:** месяц непрозрачен (`opacity: 1`), звёзды `opacity: t` (проявляются к порогу).

1. **HTML:** сразу после `<body>` добавить:

```html
<img id="ptrMoon" src="icons/icon-192.png" alt="" width="48" height="48">
<div id="ptrStars" aria-hidden="true"></div>
```

2. **CSS** (рядом с `#fDatePh`-гейтом, ~строка 115):

```css
/* Месяц и звёзды на небе-подложке: красятся после фона html (небо), но до
   фона body (форма) — на десктопе закрыты формой, при PTR тело сдвигается
   и открывает их. Горизонталь месяца привязана к колонке body
   (max-width 640px, центрирована): над заголовочным 🌙 при любой ширине. */
#ptrMoon {

@media (prefers-color-scheme: dark) {
```

CSS-дефолты дают состояние «без тяги» (светлая: месяц 0; тёмная: месяц 1 — виден в любом раскрыве). Инлайн-стили из JS на время тяги перекрывают дефолты, сброс — возврат к дефолтам. Селектор `#titleH1 img` переживёт перезапись innerHTML заголовка при смене темы (index.html:1477); класс `ptr-moon` ставит только VK-шный PTR-IIFE (touch-события мышью не генерируются — десктоп не затронут).

3. **JS, PTR-IIFE** (index.html:461–527):

   - Генерация звёзд (однократно, при входе в IIFE): ~25 точек `document.createElement("i")`, случайные `left` 0–100%, `top` 0–110px, размер 1–2px (чередование), аппенд в `#ptrStars`.
   - Хелпер:

```js
function ptrSky(t) {
    const dark = resolveDark();
    document.getElementById("ptrMoon").style.opacity = dark ? "1" : String(t);
    document.getElementById("ptrStars").style.opacity = dark ? String(t) : "0";
}
```

   - `touchmove`, после вычисления `dist`: `ptrSky(Math.min(dist / THRESHOLD, 1));` и `document.documentElement.classList.add("ptr-moon");` (заголовочный 🌙 гаснет сразу с началом тяги).
   - Сброс к CSS-дефолтам — хелпер `ptrSkyClear()`: у `#ptrMoon` и `#ptrStars` очистить `style.opacity`; вызывать в `ptrReset()` первой строкой вместе со снятием класса `ptr-moon`, и в `ptrEnd()` ветки срабатывания (перед transition/reload).
   - `touchcancel`-обработчик использует `ptrReset()` — покрыт автоматически.
   - Смена темы посреди тяги учитывается в следующем `touchmove` (`resolveDark()` на каждом вызове).

Параметры (число звёзд, высота полосы 140px, размер точек, скорость проявления) — легко подстроить после визуальной проверки.

### Валидация дополнений

1. Touch, светлая тема: тяга начинается — 🌙 в заголовке пропадает сразу; большой месяц в раскрывшемся небе проявляется постепенно и полностью видим к порогу (~70px); звёзд нет; отпустить до порога — заголовок восстановился, месяц растворился, контент вернулся.
2. Touch, тёмная тема (в т.ч. принудительная VK): месяц виден сразу при любом раскрыве, звёзды проявляются по мере тяги и полностью к порогу.
3. Тяга за порог — толчок (план ptr-taptic), защёлкивание, reload.
4. Смена темы VK посреди тяги — следующее движение перекрашивает небо по новой теме.
5. Десктоп (любая ширина): месяц/звёзды закрыты формой (за непрозрачным фоном `body`); в боковом небе широкого окна тёмной темы месяц виден — ожидаемо и не мешает; заголовочный 🌙 всегда на месте.
6. Облачный обмен: 📤 крутится целиком со своей иконкой, метка не меняется; блокировка/разблокировка как раньше.

## Контекст (реализовано)

Облачный обмен асинхронен и долог: `vkDbPut` пишет записи в `VKWebAppStorageSet` последовательными await, `vkDbGet` читает 990 ключей; в Яндекс-режиме те же кнопки 📤/📥 идут через presign + fetch. Тапы по 📤/📥 во время незавершённой операции интерливят запросы (чтение полузаписанной базы, двойной PUT). Отзыв согласия (`vkDbClear`/`cloudDelete`) тоже пишет в облако и участвует в той же гонке. Решение — `cloudBusy`/`cloudLock`/`cloudRun`: disable у 📤/📥 и чекбокса согласия на время обмена, спиннер в нажатой кнопке, снятие в `finally`. Детали ниже — исходная редакция.

## Изменение

1. Добавить общий сторож (рядом с `cloudPut`/`cloudGet`, ~строка 2103):

```js
// ---- Блокировка облачных операций (гонка 📤/📥/отзыв согласия) ----
let cloudBusy = false;
function cloudLock(on, spinBtn) {
    cloudBusy = on;
    for (const id of ["cloudPutBtn", "cloudGetBtn", "pdConsent"]) {
        const b = document.getElementById(id);
        if (!b) continue;
        b.disabled = on;
        if (b === spinBtn) {
            if (on) { b.dataset.label = b.textContent; b.textContent = "⟳"; b.classList.add("busy-spin"); }
        } else if (!on && b.dataset.label !== undefined) {
            b.textContent = b.dataset.label; delete b.dataset.label; b.classList.remove("busy-spin");
        }
    }
}
function cloudRun(op, spinBtn) {
    if (cloudBusy) { status("Дождитесь завершения обмена с облаком", true); return; }
    cloudLock(true, spinBtn);
    return Promise.resolve(op()).finally(() => cloudLock(false));
}
```

CSS (в блок стилей кнопок, после `button:hover`):

```css
@keyframes lrSpin { to { transform: rotate(360deg); } }
.busy-spin { display: inline-block; animation: lrSpin 1s linear infinite; }
```

2. Разметка: `onclick="cloudPut()"` → `onclick="cloudPut(this)"` и `onclick="cloudGet()"` → `onclick="cloudGet(this)"` (index.html:243–244); сигнатуры функций получают параметр `btn` и передают его в `cloudRun(op, btn)`.

3. `cloudPut()` (index.html:2103): тело обернуть в `cloudRun(async () => { ... }, btn)` — VK-ветка `vkDbPut()` получает `await`, промис-цепочка Яндекс-ветки возвращается как есть.

4. `cloudGet()` (index.html:2119): аналогично.

5. `initPdConsent` (index.html:1789–1816), ветки отзыва: `vkDbClear()` / `cloudDelete(token)` обернуть в `cloudRun(...)` (без `spinBtn` — триггер чекбокс, не кнопка; кнопки просто сереют). Дополнительный busy-контроль в обработчике не нужен: чекбокс `pdConsent` дизаблится вместе с кнопками (шаг 1), снять галочку во время обмена физически нельзя.

## Заметки

- Спиннер — инлайновый вращающийся ⟳ в нажатой кнопке (средствами страницы; у бриджа ВК нет публичного ивента глобального лоадера). Исходная иконка сохраняется в `dataset.label` и восстанавливается в `finally` — на любом исходе, включая ошибки сети.
- Кнопки и чекбокс `disabled` сереют UA-стилем — отдельный CSS не нужен; до логина/согласия кнопки и так скрыты (`display:none`).
- `confirmAuto` внутри `vkDbGet` (замена/объединение) удерживает блокировку до выбора пользователя — осознанно: слияние с приходящим PUT опаснее лишних секунд ожидания.
- Миграция/указатели версий (`vkPointerPut`, `maybeMigrateDb`) идут до UI и на старте — вне охвата.

## Валидация

1. VK: тап 📤 — в кнопке крутится ⟳, 📥 и чекбокс серые; по завершении иконка 📤 восстановлена, кнопки активны. Тап 📤 и тут же 📥 — второй тап игнорируется.
2. VK: двойной быстрый тап 📤 — второй игнорируется, записи не задваиваются.
3. Яндекс-режим: то же для presign/fetch-пути.
4. Попытка снять галочку согласия во время обмена — чекбокс серый и не реагирует; после завершения отзыв проходит штатно.
5. Ошибки сети (авиарежим): finally снимает блокировку, исходные иконки 📤/📥 восстановлены, кнопки снова активны.
