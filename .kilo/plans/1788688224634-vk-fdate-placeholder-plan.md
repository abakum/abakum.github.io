# План: в VK-режиме на телефоне не показывать оверлей «Дата» (работает нативный плейсхолдер)

## Решение (по итогам обсуждения)
В мобильном VK-контексте (`vk_platform` = `android`/`iphone`) оверлей `#fDatePh` убрать совсем: нативный плейсхолдер дейт-инпута в VK WebView виден и контрастен, пусть рисует его UA. Оверлей остаётся только в мобильных браузерах вне VK (Android Chrome и т.п.), где UA-плейсхолдер не контрастен.

## Режимы (важно не путать)
- **GitHub Pages (PWA)**: страница в обычном браузере, без `vk_app_id` → `.vk` не ставится. Здесь всё работает, не трогаем.
- **Хостинг VK (мини-апп), мобильный**: тот же `index.html` (сборка `build/`, `scripts/copy-build.js`) на origin VK. VK-клиент при запуске мини-аппа дописывает `vk_app_id` в URL → `vkminiapp` (index.html:571) → класс `.vk` на `<html>` (index.html:575). В этом режиме пользователь видит баг.
- **Хостинг VK (мини-апп), десктоп Chrome (`vk.ru/app54746591`)**: launch-параметры подставляет веб-сервер VK, встраивая мини-апп в iframe с `vk_app_id` в URL. `vkminiapp`/`.vk` срабатывают и здесь, но бага нет: медиазапрос `(hover: none) and (pointer: coarse)` не выполняется, оверлей скрыт (`display:none`, index.html:213), работает нативный плейсхолдер.

Детекцию писать не нужно — она уже есть и корректно различает режимы: флаг определяется только по факту запуска мини-аппа (наличие `vk_app_id` в URL независимо от того, кто его туда добавил — клиент или сервер VK), а вид оверлея дополнительно ограничен touch-медиазапросом.

### Как отличить десктопный Chrome (`vk.ru/app...`) от webview VK-приложения
Если когда-нибудь понадобится программное различение (для этого фиксa НЕ требуется):
1. `vkBridge.send("VKWebAppGetLaunchParams")` → `vk_platform`: `"desktop_web"` в десктопном браузере, `"android"`/`"iphone"` в приложении VK. Официальный способ, vk-bridge уже подключён.
2. `navigator.userAgent`: webview приложения содержит `Android` + `; wv)` (часто `VKMobileApp`); десктопный Chrome — нет.
3. Косвенно: медиазапрос `(hover: none) and (pointer: coarse)` — истина в мобильном webview, ложь на десктопе.

## Проблема
Оверлей «Дата» (`#fDatePh`, index.html:415) — HTML-текст поверх пустого `<input type="date">`, включается медиазапросом `@media (hover: none) and (pointer: coarse)` (`opacity:.72`, подложка `var(--surface)`, index.html:220-232). Он был задуман как замена нативного плейсхолдера, но в VK WebView нативный плейсхолдер тоже рисуется и «высовывается» из-под полупрозрачного оверлея — текст двоится. Поскольку в VK WebView нативный плейсхолдер виден и сам по себе, оверлей там не нужен вовсе.

## Изменение (один файл `LunarReturns/index.html`)
Сразу после блока `@media (hover: none) and (pointer: coarse) { #fDatePh {...} }` (после строки 232) добавить:

```css
/* В VK WebView нативный плейсхолдер дейт-инпута виден и контрастен —
   оверлей «Дата» там не нужен (без него текст не двоится). */
html.vk #fDatePh { display: none; }
```

- Синхронная грань без `vk_platform`/async-вызовов: в webview VK-приложения на телефоне одновременно выполняются touch-медиазапрос и класс `.vk` (ставится по `vk_app_id`, index.html:571-575) — оверлей скрыт, работает нативный плейсхолдер.
- Десктопный Chrome (`vk.ru/app...`): `.vk` есть, но touch-медиазапрос ложен — оверлей и так скрыт, поведение не меняется.
- Android Chrome (не VK): `.vk` нет — оверлей с `opacity:.72` работает, как раньше.
- JS не трогается: `syncDatePh` (index.html:1290-1294) и правила `#dateWrap.filled` / `:focus-within` (index.html:230-231) остаются — при заполнении/фокусе оверлей и так скрывался бы, теперь он скрыт всегда в VK, что безопаснее.
- Правила `html.theme-dark #fDatePh { opacity:.54 }` (index.html:216-219) на десктопе, где оверлей `display:none`, — не затрагиваются.
- Обновить комментарий над `#fDatePh` (index.html:209-212): оверлей — только для мобильных браузеров вне VK.
- VK-сборка: `npm run build` копирует index.html как есть (copy-build.js:14-19), отдельных действий не требуется.

## Риски
- Если в какой-то теме VK WebView нативный плейсхолдер всё же окажется невидимым (старый комментарий index.html:209-210 упоминал инверсию при расхождении color-scheme), пустое поле даты будет выглядеть пустым — но выбор даты по тапу и `showPicker` (index.html:1154-1155) продолжают работать. При проверке в мини-аппе убедиться, что плейсхолдер виден в светлой и тёмной темах.

## Что не делаем
- Не меняем вид в GitHub Pages-режиме и обычных мобильных браузерах: `opacity:.72` оверлея остаётся.
- Не трогаем детекцию VK и JS: `vk_app_id`/`.vk` уже работают; `vk_platform` для фиксa не требуется (класс `.vk` на телефоне + touch-медиазапрос дают нужную грань синхронно).

## Валидация
1. DevTools → мобильная эмуляция (touch), `LunarReturns/index.html` без параметров: оверлей «Дата» виден и полупрозрачен, как раньше (Android-браузер не задет).
2. То же с `?vk_app_id=1`: оверлея нет; поле даты пустое (нативный плейсхолдер в эмуляции может не рисоваться — это ожидаемо, проверка 3 решающая).
3. В реальном мини-аппе (`vk.ru/app54746591` с телефона, Android и iOS, светлая и тёмная темы): виден только нативный плейсхолдер, текст не двоится; тап открывает календарь; после выбора даты поле выглядит как раньше.
4. Десктопный Chrome (`vk.ru/app54746591`): работает нативный плейсхолдер (регресса нет).
