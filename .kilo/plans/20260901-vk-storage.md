# Plan: Сохранение/загрузка базы в VK Mini App через VKWebAppStorage (LunarReturns)

## Цель
В VK-версии LunarReturns включить сохранение/загрузку базы (кнопки 📤📥) через
VK Cloud Storage (`VKWebAppStorageSet/Get` через vk-bridge). Веб-версия с GitHub
работает по-прежнему через Яндекс-Oauth + Яндекс Cloud Functions + S3.

**Скоуп:** только хранение базы. Пуши (🔔) в VK — отложено (нужен серверный
планировщик), кнопка в VK остаётся скрытой.

## Решения (согласовано)
1. Хранение — `VKWebAppStorageSet/Get`: **одна запись db = один ключ** (не
   шардирование JSON-строки). Запись `{n, d}` компактна и всегда влезает в
   лимит 4096 байт; до 1000 ключей на пользователя — до 1000 записей базы.
   Ключи — индексы `"0".."N-1"`. Хранилище у каждого VK-пользователя своё,
   в отличие от общей S3-корзины веб-версии.
2. Пуши VK — вне скоупа.
3. Согласие ПДн — текст зависит от платформы:
   - веб (GitHub): «Яндекс.Облаке» → «облаке Яндекс», «Яндекс.Облака» → «облака Яндекс»;
   - VK Mini App: «облаке ВКонтакте», «облака ВКонтакте».
   📤📥 видимы только при согласии; 🔑 Яндекса в VK скрыт; отзыв согласия
   затирает данные в VK-хранилище.
4. Детект VK — явный (`vk_app_id` в URL), а не по падению регистрации SW.
5. vk-bridge — локально в `LunarReturns/vendor/`, без CDN.

## Изменения

### 1. `LunarReturns/vendor/vk-bridge.min.js` (новый)
Скачать minified browser-bundle `@vkontakte/vk-bridge` (v3+, dist/browser.min.js)
и положить в репозиторий.

### 2. `LunarReturns/index.html`
- Подключить `<script src="./vendor/vk-bridge.min.js"></script>` до основного
  `<script>` (глобал `vkBridge`).
- **Детект VK:** в начале init-блока
  `const vkminiapp = new URLSearchParams(location.search).has("vk_app_id");`
  (заменяет `let vkminiapp = false;` и взведение по `.catch()` регистрации SW).
  При `vkminiapp` не регистрировать SW вовсе; `applyVkUi()` вызывать сразу.
- **Тексты согласия (платформо-зависимые):** в статичном HTML (строка 174 и
  `confirm()` на строке 1298) — Яндекс-вариант по умолчанию:
  - «…ПДн третьих лиц в облаке Яндекс (🔑📤) согласно 152-ФЗ и GDPR»;
  - «Отзыв согласия удаляет ПДн из облака Яндекс.»;
  - confirm отзыва: «Удалить ПДн из облака Яндекс? Локальная база сохранится.».
  В **`applyVkUi()`** (VK-режим) — JS-подстановка VK-варианта в те же места
  (лейбл: обернуть текстовые узлы в span'ы с id, например `pdConsentText` и
  `pdWithdrawNote`, чтобы менять только текст, не трогая чекбокс):
  - «…в облаке ВКонтакте (📤📥)…» (🔑-подсказку в VK не показывать);
  - «Отзыв согласия удаляет ПДн из облака ВКонтакте.»;
  - confirm отзыва в VK: «Удалить ПДн из облака ВКонтакте? Локальная база
    сохранится.».
- **Хранилище VK (новые функции):**
  - `vkStorageSet(pairs)` / `vkStorageGet(keys)` — обёртки над
    `vkBridge.send("VKWebAppStorageSet"/"VKWebAppStorageGet", …)`
    (`StorageSet` принимает массив `{key, value}`).
  - **Одна запись = один ключ.** `vkDbPut()`: сначала `vkStorageGet` текущих
    ключей `"0".."999"` для определения прежнего max занятого индекса; затем
    для `i` в `0..db.length-1` записать ключ `String(i)` = `JSON.stringify(db[i])`;
    лишние хвостовые ключи (индексы ≥ `db.length` из прежнего максимума)
    затереть `""` (удаления в bridge нет). Guard: `db.length > 999` → ошибка
    «слишком много записей».
  - `vkDbGet()`: `vkStorageGet(["0".."999"])`, собрать значения в порядке
    индексов, пропускать пустые, `JSON.parse` каждую, склеить в массив,
    провалидировать каждую запись (`validRecord`, как в `cloudGet`).
- **Ветвление `cloudPut`/`cloudGet`:** при `vkminiapp` идут через `vkDbPut`/
  `vkDbGet` (тот же UX: confirm «заменить/объединить», сид «Ада» при пустом
  хранилище — без ветки с днём рождения Яндекса), иначе — существующий
  Яндекс-путь без изменений.
- **`applyPdConsent()`:** в VK-режиме — скрыть `loginBtn`, показывать 📤📥 при
  согласии; в вебе — как сейчас.
- **Отзыв согласия в VK (`change` у `#pdConsent`):** при `vkminiapp` после
  подтверждения вызвать затирание ключей (все `"0".."N-1"` → `""`) вместо
  `cloudDelete`.
- Проверить, что `saveDb()`/`updatePushDates()` и прочее не завязаны на
  `vkminiapp` иначе, чем уже есть (guard в `updatePushDates` остаётся).

## Риски / допущения
- VKWebAppStorage не имеет удаления ключей — отзыв согласия и уменьшение базы
  затирают ключи пустой строкой (для 152-ФЗ удаление содержимого; пустые
  ключи-плейсхолдеры остаются).
- Одна запись = один ключ → максимум ~1000 записей на пользователя (лимит VK);
  guard при превышении.
- Запись с очень длинным именем (>4096 байт JSON) — практически недостижимо;
  при ошибке VK `message` показывается в статус-строке.
- vk-bridge фиксированной версии в репо — обновлять вручную.

### Отклонения от плана
- `VKWebAppStorageSet` принимает **одну** пару `{key, value}`, а не массив
    пар (проверено по `@vkontakte/vk-bridge@3.0.2/dist/types/data.d.ts`) —
    запись выполняется последовательно, по одному `send` на запись.
- Проверка формата: `VKWebAppStorageGet` — `{ keys: string[] }` →
    `{ keys: [{key, value}] }`; `VKWebAppStorageGetKeys` —
    `{ count, offset }` → `{ keys: string[] }`; использованы как есть.
