# LunarReturns: сохранение отсортированной базы в localStorage

Файл: `LunarReturns/index.html`.

## Баг

В `submitRecord()` `saveDb()` вызывается до `sortDb()`:
- строки 423-427 (редактирование): `db[editingIdx] = rec; saveDb();`
- строки 428-434 (добавление): `db.push(rec); saveDb();`
- сортировка только на строке 437, после сохранения.

Итог: в localStorage пишется неотсортированный массив; после F5 `loadDb()` (строки 314-327) читает его как есть — список снова не отсортирован.

В `pasteDb()` (строки 627-629) и `cloudGet()` (строки 747-749) порядок правильный: `sortDb()` до `saveDb()`.

## Изменения

1. **`submitRecord()` — сортировать до сохранения, в обеих ветках:**
   - Ветка редактирования: после `db[editingIdx] = rec;` вставить `sortDb();` (и пересчёт `selectedIdx`/`editingIdx` см. п. 2), затем `if (!saveDb()) { ... }`.
   - Ветка добавления: после `db.push(rec);` вставить `sortDb();`, затем `if (!saveDb()) { ... }`.
   - Убрать ставший лишним блок строк 436-438 (`const sel = ...; sortDb(); selectedIdx = ...;`), перенеся сохранение/восстановление `selectedIdx` внутрь веток до `saveDb()`.

2. **Аккуратность с индексами при сортировке в ветке редактирования:**
   - До подмены записи запомнить объекты: `const sel = selectedIdx >= 0 ? db[selectedIdx] : null; const editingRec = db[editingIdx];`
   - После `db[editingIdx] = rec; sortDb();` восстановить: `selectedIdx = sel ? db.indexOf(sel) : -1; editingIdx = db.indexOf(editingRec);` (далее `cancelEdit()` сбросит `editingIdx` в −1, как и раньше).
   - В ветке добавления `selectedIdx` восстанавливать так же (`db.indexOf(sel)`), `editingIdx` там всегда −1.
   - Откат при ошибке `saveDb()` уже существует (`db[editingIdx] = old; return;` / `db.pop(); return;`) — сохранить как есть; после отката список не перерисовывается, поведение прежнее.

3. **`loadDb()` — сортировать при загрузке** (лечит уже сохранённые неотсортированные базы): после чтения/фильтрации из localStorage (строка 319) и перед записью демо-записи Ады вызвать `sortDb();`. Вызов безопасен: `sortDb` объявлен как `const`-стрелка на строке 391 — проверить, что `loadDb()` не вызывается до её инициализации (вызов идёт из `init()`/обработчика `DOMContentLoaded` в конце скрипта; если `loadDb()` вызывается раньше строки 391 — перенести объявление `sortDb` выше `loadDb`).

## Проверка

- Добавить записи с датами вразнобой → список отсортирован; F5 → порядок сохранён.
- Редактировать запись, сменив дату на более позднюю → после F5 она на новом месте.
- Выбранная запись (подсветка) не «подменяется» после добавления/редактирования другой записи.
- Удалить все записи → сеется Ада; добавить первую свою запись → Ада исчезает (как раньше).
- Вставка базы (📋) и загрузка из облака (📥) — поведение без изменений.
- `node --check` на извлечённом скрипте; ручная проверка в браузере.

## Вне области

- Логика расчётов (титхи, фаза, зодиак), QR, облако — без изменений.
