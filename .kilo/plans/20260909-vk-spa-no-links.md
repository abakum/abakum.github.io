# VK-модерация: без навигаций и редиректов; хранение — облако ВК

## Контекст и решения

Модерация отклонила мини-апп: `<a href>` в DOM и редирект в браузер на Android
(скриншот — S3 `AccessDenied`, `BucketName: app54746591`: редирект автопереноса
увёл на мёртвый origin прежней версии). Приложение — один HTML
(`LunarReturns/index.html`), уже SPA (hash-роутер `#N`); проблема —
cross-document навигации и origin-привязанное localStorage.

Принятые решения:
1. **Миграцию через location.replace убрать полностью** (никакого iframe).
2. **Настройки (не ПДн) — всегда в облаке ВК** (VKWebAppStorage), write-through.
3. **База — в облаке ВК при согласии ПДн** (ключи «0»..«989», как у 📤/📥).
4. **Автовосстановление на свежем origin**: детект смены версии/origin —
   **по пустоте сохранённой ширины колонки** (`lunarreturns.colw`, существующий
   флаг `window.__lrFreshOrigin` из раннего head-скрипта, index.html:77),
   **не по пустоте базы**.
5. **Не писать `<a href>` в DOM в VK-режиме**.

Не навигации, оставить: PTR `location.reload()` (:936, тот же URL),
hash-роутер `#N`, `VKWebAppInit`, `<link href>` (не якорь), QR (кодирует данные).

## Задачи

### 1. Удалить миграцию (весь механизм)
- Serve-режим `#lr_migrate` с `location.replace` (:1002-1018).
- Приём `#lr_db`/`#lr_fail` из хэша (:1028-1043) и `lrLsPending` (:1020-1025)
  с применением `applyLsParams` (:1879, :1860-1878) — логику применения
  параметров переиспользовать для восстановления из облака (п.3), хэш-разбор
  удалить.
- `maybeMigrateDb()` (:2679-2697), `showMigrateFallback()` (:2700-2713, вместе
  с генерацией `<a href>`), `vkPointerGet()` (:2654-2664), `vkPointerPut()`
  (:2668-2673) и вызовы `vkPointerPut` (:1240, :3200), `maybeMigrateDb` (:3201).
- Константы/утилиты: `LR_ORIGIN_PREFIX`, `LR_ORIGIN_RE`, `LR_MIGRATE_MAX_TRIES`,
  `lrAttempts()`, `lrHashParams()` (если больше никем не используется),
  флаг `lrMigrated` и статус «База перенесена» (:3199).
- `lrSeedJson()`/`dbIsTrivial()` (:980-988) **оставить** — нужны импорту
  (:2246), `vkDbGet` (:2769) и облачному импорту (:2869); в триггер
  автовосстановления НЕ входят (см. п.3.2).
- `window.__lrFreshOrigin` в head-скрипте (:77) **оставить как есть**.

### 2. Настройки в облаке ВК (write-through)
- Ключи — текущий `LR_LS_KEYS` (:618): `DAYS_KEY`, `PD_CONSENT_KEY`,
  `PD_PUSH_CONSENT_KEY`, `VKPUSH_KEY`, `THEME_KEY` (не ПДн; `VKPUSH_PROBE_KEY`
  не переносим — stage-only).
- Схема ключей VKWebAppStorage: `lr_s_<имя локального ключа>` (5 ключей,
  не конфликтует с «0»..«989» базы; бюджет 1000 ключей: 990+5).
- Центральный хелпер `lsSet(key, value)` вместо прямых `localStorage.setItem/
  removeItem` для этих ключей; в VK-режиме (`vkminiapp && vkBridge`) он же
  делает `vkStorageSet("lr_s_"+key, value ?? "")` fire-and-forget (`.catch(()=>{})`).
  Найти все места записи: `applyTheme` (:697), чекбоксы согласий, дни, VKPUSH.

### 3. Автовосстановление на запуске (VK-режим, после VKWebAppInit)
Порядок строго: настройки → база (согласие читается уже из восстановленного
localStorage).
1. **Настройки**: `vkStorageGetKeys()` → фильтр `lr_s_` → `vkStorageGet` →
   для каждого ключа: если в localStorage значения нет — записать локально и
   применить к UI (тема — `applyTheme()`, чекбоксы/кнопки — как делает
   `applyLsParams`). Ошибки — молча (`.catch`). Конфликт (оба есть) —
   побеждает локальное значение.
2. **База**: триггер — `window.__lrFreshOrigin` (пустая ширина колонки,
   НЕ пустота базы) **и** `pdConsentGiven()` → автоматически `vkDbGet()`
   (существующая, :2731; пустое облако даёт сид «Ада»/«Я» из bdate).
   На свежем origin локальная база — сид, поэтому диалог «объединить/заменить»
   в `vkDbGet` не сработает — автоподтяжка молча. Гонка с ручной 📋-вставкой
   в первые секунды после запуска — принята.
3. Push/📤/📥 остаются как есть: запись базы в облако — вручную 📤
   (`vkDbPut`, согласие-гейт уже есть).

Граничный случай (принято): пользователь не нажал 📤 на старой версии →
облако пустое → на новой базе нет; после первого запуска origin уже не
«свежий», автовосстановление не повторится — остаётся ручной 📥. Документировать
в README.

### 4. Убрать `<a href>` из DOM в VK-режиме
- Статический `<a id="bugLink">` (:594) удалить из разметки; создавать через JS

- `renderSwVersion()` (:1991-1999): **не трогать** — stage не модерируется,

- `loginYandex()` (:2459): первой строкой `if (vkminiapp) return;` (OAuth
  `location =` :2474 недостижим в VK — страхуем).

## Проверка

1. `grep -n "<a" LunarReturns/index.html` — в статической разметке якорей нет;
   JS-якоря — только ветки `!vkminiapp` (bugLink) и stage (версия, :1994):
   в prod-сборке VK-пути якорей нет.
2. `grep -n "location.replace\|location\s*=" LunarReturns/index.html` —
   осталось только OAuth под guard'ом.
3. `grep -n "lr_migrate\|lr_db\|lr_fail\|lr_origin\|lrAttempts\|vkPointer"` — пусто.
4. Stage-деплой (автоматический workflow, локально `npm run build` не запускать):
   - новый origin: настройки восстановились; при согласии и пустой ширине
     колонки — база подтянулась; топ-уровень не навигирует;
   - без согласия: только настройки;
   - консент отозван: база не тянется.
5. Android-клиент (prod): запуск не открывает внешний браузер; theme/PTR работают.
6. Stage: версия остаётся ссылкой на прямой VK-URL; автовосстановление и
   «no anchors» в prod не сломаны.
7. Web (github.io): поведение без vkBridge не изменилось; bugLink на месте.
