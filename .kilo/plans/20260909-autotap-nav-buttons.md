# План: убрать ключ «первого открытия», автотап при каждом старте + кнопки 🔼🔽 между именинниками

Файл: `LunarReturns/index.html` (единственный файл правки; `sw.js` ключ не трогает).

## Суть

Сейчас `AUTOTAP_KEY = "lunarreturns.autotap"` (iso-дата МСК) хранит факт
«первого открытия с авт выбором именинника» — автотап выполняется раз в сутки
(`autoTapToday()`, line 2517: `if (localStorage.getItem(AUTOTAP_KEY) === iso) return;`).

Требуется:
1. Убрать `AUTOTAP_KEY` полностью — автотап выполняется при каждом открытии.
2. Всегда выбирать первого именинника (первую запись БД с сегодняшним MM-DD).
3. В row-кнопок результата (после 🔙 `srcBtn`) рисовать навигацию по сегодняшним
   именинникам:
   - именинник один → кнопок нет;
   - первый из нескольких → только 🔽;
   - промежуточный → 🔼 и 🔽;
   - последний → только 🔼.
4. При автотапе на старте делать «подъезд» к результату и для одноколоночного
   (`resultSec.scrollIntoView`), и для двухколоночного (`alignResultToRow`).

### 2. Подъезд к результату при старте (оба режима)
В `autoTapToday()` вместо
```js

```
вызывать `selectRecord(idx)` — он уже делает `renderList` + `renderResult` и
подъезд: two-col → `alignResultToRow(i)`, one-col →
`resultSec.scrollIntoView({block:"start"})` (line 1504–1507).
Нюанс: `row.click()` дополнительно вызывал `startEdit(i)` (prefill формы,

подъезд. То же для `hashSelect()` (line 2502)? — нет: `#N` это явная ссылка,
там оставить как есть (вне скоупа запроса).

### 3. Список сегодняшних именинников и кнопки 🔼🔽
- В `autoTapToday()` поиск уже есть: `db.findIndex(r => mds.includes(r.d.slice(5)))`.
  Вынести вычисление в helper, например
  `todayIdxs(mds)` → массив индексов db, чтобы переиспользовать при рендере кнопок.
- В HTML btnrow (line 561, после `srcBtn`) добавить две кнопки:
  ```html
  <button type="button" id="prevBtn" onclick="stepToday(-1)" title="Предыдущий именинник" style="display:none;">🔼</button>
  <button type="button" id="nextBtn" onclick="stepToday(1)" title="Следующий именинник" style="display:none;">🔽</button>
  ```
  Важно: `srcBtn` в two-col скрывается CSS-правилом `#ptrWrap.two-col #srcBtn`
  (line 473) — новые кнопки НЕ должны попадать под это правило; скрывать их
  только инлайново/JS по логике ниже (в обоих режимах).
- Логика (функция `updateTodayNav()`):
  - вычислить `mds` для сегодняшнего дня (та же логика MM-DD + 02-28→02-29,
    вынести в helper `todayMds()`, переиспользовать в `autoTapToday`);
  - `idxs = todayIdxs()`; позиция `p = idxs.indexOf(selectedIdx)`;
  - если `p < 0` или `idxs.length < 2` → обе кнопки скрыты;
  - `p === 0` → только 🔽; `0 < p < last` → 🔼 и 🔽; `p === last` → только 🔼.
- `stepToday(dir)`: `p ± 1` → `selectRecord(idxs[p±dir])` + `startEdit(...)` —
  консистентно с тапом по строке.
- Вызовы `updateTodayNav()`: в конце `renderResult()` (после показа результата)
  и в `hideResult()` (скрыть обе кнопки); кнопки завязаны на selectedIdx,
  поэтому пересчёт при каждом рендере результата достаточен.

## Риски / заметки
- После удаления ключа у существующих пользователей в localStorage останется
  нечитаемый `lunarreturns.autotap` — безвредно; можно не чистить (ключ не в
  списке очистки).
- `renderResult()` вызывается из многих мест (selectRecord, toggleDetail,
  renderNow при смене дня?) — `updateTodayNav()` должен быть дешёвым (массив db
  маленький, md-строки).
- Смена суток при открытой странице: `renderNow()` пересчитывает результат —
  проверять, что кнопки обновились через `renderResult`/`updateTodayNav`-цепочку;
  при сомнении вызвать `updateTodayNav()` и из `renderNow()`.

## Валидация
Ручная проверка (локальный запуск — открытие index.html в браузере; `npm run
build` НЕ запускать, см. AGENTS.md):
1. БД с одной записью на сегодня: автотап выбирает её, кнопок 🔼🔽 нет,
   one-col — страница подъезжает к результату; two-col — результат напротив
   строки.
2. Две записи на сегодня: у первой только 🔽; тап 🔽 → вторая, только 🔼;
   подъезд работает в обоих режимах.
3. Три записи: первый → 🔽; второй → 🔼🔽; третий → 🔼.
4. Перезагрузка страницы: автотап срабатывает снова (ключа больше нет).
5. Записей на сегодня нет → результата нет, кнопок нет; `#N`-хэш приоритетен.
