# VK-бот юбилеев LunarReturns (Node.js)

## Цель
Бот сообщества ВКонтакте в `/home/koka/src/LunarReturns/bot` (Node.js, без фреймворков):
- читает сообщения сообщества через **Long Poll** (решено);
- на сообщение о человеке/паре сразу отвечает списком лунно-солнечных юбилеев и сохраняет запись в JSON-базу на диске. Формы триггера: `Костя 19630927`, `Дедушка Костя 1963-09-27 14:30`, `… 12:30 (МСК+2)`, `… 12:30 (Пермь)`, `… 12:30 UTC+5`;
- пара `Костя+Галя 19780512` — **одна запись с одной датой** (решено), в списках годовщин добавляются названия свадеб (`WED` из приложения);
- каждый год 27.09 бот сам отправляет в тот же диалог сообщение со списком юбилеев по каждой записи с датой 0927;
- процесс живёт постоянно на машине koka (решено), без cron.

## Источник логики
Портировать из `LunarReturns/index.html` (это чистый JS, копируется почти дословно):
- `moonNew(date)` (строка 1078) — фаза/долгота Луны, без библиотек;
- `tithiInt`, `TITHI_PHASE`, `phaseName`, `moonZodiacInt/Name`, `sunZodiacInts/Names`, `chineseZodiacName`, `wdLocale`, `legend`, `la(birth)` (1201), `addYears`, `WED`, `ageSuffix` (1618), формат вывода как `renderResult()` (1632): `Имя ДД.ММ.ГГГГ + возраст(+ свадьба)` затем строки `la()`.
- `TZ_MS` и полдень по умолчанию: дата без времени → `Date.UTC(y, m-1, d, 12, 0, 0)` (см. `renderResult`);
- `CITY_ZONE`, `ZONE_EPOCHS`, `cityDiffMin` (строки 738–744) и логика нормализации в МСК из `submitRecord()` (строки 1404–1419).

## Поведение
1. **Long Poll**: `groups.getLongPollServer` → GET `?act=a_check&key&ts&wait=25` → события `message_new`. При ошибке/смене `failed` — заново получить сервер. `access_token` групповой из env `VK_TOKEN` (или `.env`-файл рядом), scope: messages.
2. **Разбор сообщения** (решено: поддерживаются все формы):
   - имя — любые слова, включая пробелы: `Дедушка Костя`; `+` в имени = пара;
   - дата: `ГГГГММДД` или `ГГГГ-ММ-ДД`;
   - время (опционально): `ЧЧ:ММ` или `ЧЧММ`/`ЧЧ` — нет времени → полдень 12:00;
   - часовой пояс (опционально): `(МСК+2)`, `(Пермь)`, `UTC+5`, `ГГГГ+5` — в скобках или без.
   Regex примерно: `^\s*(.+?)\s+(\d{4})-?(\d{2})-?(\d{2})(?:\s+(\d{1,2})[:.]?(\d{2})?)?\s*(?:\(\s*([^)]+?)\s*\)|\b((?:UTC|МСК|МСК|ГМТ|GMT)[+-]\d{1,2})\b)?\s*$`.
   - Город (`Пермь` и др.) — по таблице `CITY_ZONE`/`ZONE_EPOCHS` + `cityDiffMin(city, d)` из index.html (строки 738–744, копируются дословно, исторические декретные часы/переходы учтены); город, не найденный в таблице → ошибка с подсказкой.
   - Явный сдвиг (`МСК+2`, `UTC+5`) — фиксированный сдвиг от указанной базы (без исторического DST; упрощение).
   - Нормализация как в `submitRecord()` (строки 1404–1419): локальные дата-время переводятся в МСК → `rec = { n, d, h, m }` в МСК. Ответ сразу: текст из `la()` + примечание «Пермь 12:30 → МСК 10:30» как в приложении. Запись сохраняется в `db.json` вместе с `peerId` и обновляется при повторном триггере.
3. **Ежегодная отправка** (решено: ежедневно ровно в 09:00 МСК): таймер вычисляет ближайшие 09:00 МСК (`setInterval` каждую минуту проверяет, не наступил ли час 09:00 текущих МСК-суток, либо `setTimeout` до следующего 09:00 МСК), при наступлении проверяет записи с `MMDD == 0927`, которым в этом году ещё не отправлено (`lastSentYear < текущий год`). Отправить список в `record.peerId`, записать `lastSentYear`. Отметку делать ДО отправки и откатывать при ошибке, чтобы не задваивать. После простоя процесса догоняет пропущенное (правило lastSentYear). При старте процесса: если текущее МСК-время ≥ 09:00 и за сегодня проверка ещё не была сделана — прогнать сразу.
4. Ошибки VK/сети — в stderr с backoff; JSON-база писать атомарно (tmp+rename).

## Формат ответа (как в приложении)
```
Дедушка Костя 1963-09-27 14:30 63
<легенда рождения>
#2027г ... (строки la())
```
Для пар — суффикс свадьбы (`WED[age]`), как `ageSuffix`.

## Риски
- Портирование `la()`/`legend()` требует вычистить DOM-зависимости (`WIDE_SPACE`, `SPACE`, `document` — только константы пробелов нужны).
- Проверить точность `moonNew` — формулы идентичны приложению, расхождений быть не должно; сверить вывод бота с выводом index.html для «Ада 1815-12-10» и «Костя 1963-09-27».

## Валидация
- `node lunarreturns.js` с тестовым токеном; отправка «Костя 19630927» в ЛС сообщества → ответ совпадает (по строкам годовщин) с результатом index.html для той же записи.
- Режим без токена: `node lunarreturns.js test "Дедушка Костя 1963-09-27 12:30 (Пермь)"` печатает разбор (город→МСК) и список юбилеев, выходит — сверить с приложением для той же записи с городом Пермь.
- Проверить все 4 формы: `Костя 19630927`, `Дедушка Костя 1963-09-27 14:30`, `… 12:30 (МСК+2)`, `… 12:30 (Пермь)`, `… 12:30 UTC+5`.
- Имитация 0927: подменить `lastSentYear` на прошлый год → при старте бот отправляет сообщение.
