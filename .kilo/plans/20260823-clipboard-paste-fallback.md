# Plan: Фолбэк для кнопки 📋 (pasteDb) в LunarReturns/index.html

## Контекст
`pasteDb()` (LunarReturns/index.html:892) читает буфер через `navigator.clipboard.readText()`. В Hermit (Android WebView) чтение буфера через этот API запрещено/отклоняется → сообщение «Не удалось прочитать буфер обмена». Вставка в поле формы работает, т.к. это нативная вставка ОС, не web-API.

## Изменения (только LunarReturns/index.html)
1. Вынести логику импорта из `pasteDb` в функцию `importDbText(text)`:
   - JSON.parse → ошибки «В буфере не JSON база данных» / «Неверный формат базы»;
   - merge с `db` (существующая логика строк 905–921), финальный status.
2. `pasteDb()`:
   - если `navigator.clipboard.readText` доступен — попытаться; при reject не просто показывать статус, а открыть фолбэк-диалог (п.3);
   - если API отсутствует — сразу открыть фолбэк-диалог.
3. Фолбэк-диалог `showPasteDialog()`:
   - простой overlay (fixed, по центру) с `<textarea id="pasteFallbackArea">`, кнопками «Вставить и импортировать» и «Отмена»;
   - textarea автофокус; пользователь вставляет нативно (долгое нажатие / Ctrl+V);
   - по кнопке импорта: `importDbText(textarea.value)`, закрыть диалог; пустое значение — статус «Вставьте данные в поле»;
   - Enter/Escape — импорт/закрытие; закрытие также по клику на фон.
4. Стили overlay добавить в существующий `<style>` без новых файлов.

## Поведение после правки
- В обычном браузере — как раньше (API работает).
- В Hermit: кнопка 📋 открывает диалог, пользователь вставляет из буфера в поле нативно, база импортируется.

## Валидация
- Открыть страницу в обычном браузере: кнопка 📋 работает как раньше.
- Сымитировать отказ (например, через devtools переопределение `navigator.clipboard.readText` → reject): появляется диалог, вставка текста базы и импорт проходят.
- Проверить некорректный JSON в диалоге → «В буфере не JSON база данных».
