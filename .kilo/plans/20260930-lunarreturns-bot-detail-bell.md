# VK-бот юбилеев: реакции 👎/👀, кнопка 🔔, справка «/»

## Контекст
Работающий бот `~/src/LunarReturns/lunarreturns.js`: Long Poll, триггеры
«Имя ГГГГММДД [ЧЧ:ММ] [(пояс)]», ответы реплаем, клавиатура «/» (🗑 + пары
[религия 🔔/🔕]) только в личке, дайджест религий в 09:00 МСК, catchUp,
systemd. Реакции уже ловятся: событие `message_reaction_event`, формат
`{reacted_id, peer_id, cmid, reaction_id}`, 👎 = `reaction_id 9`, на 👎
удаляется запись ответа (reply «🗑 Запись удалена: …»).

## Решения (согласованы)
- 👀 — **не кнопка, а реакция** на ответ бота или утреннее уведомление.
  Реакция **не меняет состояние**: бот отвечает (reply на то же сообщение)
  **развёрнутым списком** этой же записи — все годы хотя бы с одним
  совпадением (порог `c > 0`), без ограничения 90 лет (семантика detailMode
  приложения). Обычные ответы и уведомления всегда сжатые (`c > 1`, <90 лет).
- 👎 — реакция, удаляет запись дизлайкнутого ответа (уже реализовано).
- 🔔 — **кнопка** в клавиатуре «/» (личный чат: ряд 1 `[🗑, 🔔]`, ряд 2 —
  религии; в групповом чате по «/» — одна кнопка `[🔔]`). Тап: список
  ближайших дней рождения записей чата на год вперёд, формат
  «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]», сортировка по дате ближайшего наступления.
- `/` отвечает текстом-справкой (не пустым символом): только про реакции —
  «Реакция 👎 — удалить событие. Реакция 👀 — детально.» (кнопки не
  описываем).
- **Владелец сообщества** (определяется через `groups.getMembers` c
  `filter=managers`, `role="creator"`, кэшируется при старте) в групповом
  чате по «/» получает полную клавиатуру `[🗑, 🔔]` (+ ряд религий), как в
  личке; остальные участники — только `[🔔]`.

## Поведение
1. **«/» (любой чат)**: текст-справка (про кнопки не пишем), например
   `Реакция 👎 — удалить событие. Реакция 👀 — детально.`
   - личный чат: клавиатура ряд 1 `[🗑, 🔔]`, ряд 2 `[☦️, ☪️, ☸️, ✝️, ✡️]`
     (пары `[религия 🔔|🔕]` как сейчас);
   - групповой чат: **владелец** — `[🗑, 🔔]`; остальные — одна кнопка `[🔔]`.
2. **🔔 тап** (payload `{c:"bell"}`): для каждой записи чата ближайшая дата
   (ММ-ДД этого или следующего года), сортировка, вывод
   «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]»; записей нет → снекбар «записей нет».
3. **Реакция 👎 (id 9)** — как реализовано: удалить запись ответа + reply
   «🗑 Запись удалена: …».
4. **Реакция 👀 (id уточняется эмпирически, константа)**: по `cmid` взять
   текст ответа/уведомления, вырезать из заголовка имя и дату, найти запись
   (пир+имя+дата) → reply на то же сообщение с развёрнутым списком
   (заголовок как обычно, годы с порогом `c > 0`, без лимита 90 лет).
   Запись не найдена — молча. Повторная 👀 — повторный развёрнутый список
   (безопасно).
5. **detailMode в коде**: `la(birth, detail = false)` — фильтр годов
   `i >= f && c > 0 || (detail ? c > 0 : c > 1) && i < 90`;
   `jubileeText(rec, note, detail)`. Обычные ответы/уведомления вызывают с
   `detail = false` (сжато); 👀-обработчик — с `detail = true`.
6. **🗑**: подтверждение — список записей чата, упорядоченный по полной дате
   рождения (с учётом ГГГГ, `r.d[ h:m]`); 🔔 — по ближайшему наступлению
   (ММ-ДД, год вперёд). **Формат строк одинаков**:
   «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]».
7. **Ответы 👀/🔔 в групповом чате — сначала в личку**: технически в
   `message_new` приходят `peer_id` (чат, ≥2000000000) и `from_id` (личный ID
   автора); в `message_event` — `user_id`, в реакции — `reacted_id`.
   - 🔔: список событий отправляем на peer `user_id` (личный чат автора);
   - 👀: развёрнутый список — на peer `reacted_id`;
   - если `messages.send` в личку падает (ошибка ВК: пользователь запретил
     сообщения от сообщества и т.п.) — повторить в групповой `peer_id`.
   Лог: «👀 → личка peer …» / «👀 → личка не удалась, в чат …».
8. Неизвестный payload — снекбар «неизвестная кнопка»; неизвестные
   `reaction_id` — только в лог (уже есть).## Задачи
1. `la(birth, detail = false)` + `jubileeText(rec, note, detail)`;
   `handleMessage`, `dailyCheck`, `catchUp` вызывают с `detail = false`.
2. **Владелец**: при старте `groups.getMembers { group_id, filter: "managers" }`
   → первый с `role === "creator"` → кэш `ownerId` (нужен скоуп «Управление
   сообществом»; при отказе — `ownerId = 0`, владельцу обычная клавиатура).
3. Клавиатуры: `relKeyboard(peerId)` (личный чат) — ряд 1
   `[🗑 {c:del}, 🔔 {c:bell}]`, ряд 2 — религии; `ownerKeyboard()` — одна
   строка `[🗑 {c:del}, 🔔 {c:bell}]` (без религий); `bellKeyboard()` — одна
   кнопка `[🔔 {c:bell}]` (остальные участники группы).
4. Триггер «/»: текст-справка «Реакция 👎 — удалить событие. Реакция 👀 —
   детально.» + клавиатура (личный — `relKeyboard`; групповой —
   `ownerKeyboard` для `from_id === ownerId`, иначе `bellKeyboard`).
5. `handleEvent`: payload `bell` → «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]» по ближайшим
   датам на год вперёд; пусто → снекбар.
5. `handleReaction`: reaction_id 9 — удаление (есть); reaction_id **👀**
   (константа `REACTION_EYES_ID`) → по `cmid` текст → запись → развёрнутый
   список: сначала в личку (`reacted_id`), при ошибке — в чат (`peer_id`).
   Точное значение id узнать первым использованием — в лог уже пишется
   `reaction_id` каждой реакции, отличной от 9.
6. Помощник `sendToUserFirst(userId, groupPeerId, text, keyboard)`:
   `messages.send(peer_id = userId)` → при ошибке `messages.send(peer_id =
   groupPeerId)`; используется в `handleEvent` (`bell`) и `handleReaction`
   (👀).
7. 🗑-подтверждение: сортировка списка по полной дате рождения
   (`r.d[ h:m]`); 🔔 — по ближайшему наступлению (ММ-ДД).
8. README: реакции 👎/👀, кнопка 🔔, справка «/», режим владельца.

## Риски
- reaction_id 👀 неизвестен заранее: первый тап покажет id в логе — вписать в
  константу и перезапустить (одна итерация «поставь 👀 — пришли лог»).
- Известные id: 4 = 👍, 9 = 👎; чужие id молча игнорируются.
- В дайджесте религий 👀 неприменим (там нет записи) — реакции на дайджест
  игнорируются (текст без заголовка «Имя ДАТА» не матчится).
- Владелец-режим требует скоуп «Управление сообществом»; без него
  `groups.getMembers` вернёт 15 — `ownerId = 0`, в группе все видят `[🔔]`
  (деградация без падения).

## Валидация
- «/» личный: текст «Реакция 👎 — удалить событие. Реакция 👀 — детально.» +
  ряд `[🗑 🔔]` + ряд религий.
- «/» групповой от владельца: тот же текст + `[🗑 🔔]` + ряд религий; от
  другого участника: текст + `[🔔]`.
- 🔔 в групповом чате: список «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]» приходит **в личку**
  автора; после запрета сообщений сообществу (или удаления диалога) — в чат.
  По возрастанию ближайших дат («Слава 2027-06-13 15:00» после «Личный30
  2026-09-30»); пустой чат — снекбар.
- 👎: запись удаляется, reply-подтверждение (регрессия).
- 👀 на ответ в групповом чате: развёрнутый список приходит в личку автора
  реакции (fallback — в чат); обычный триггер «Костя 19630927» остаётся
  сжатым.
- 🗑: список в подтверждении по возрастанию полных дат (ГГГГ-ММ-ДД: 1904
  раньше 1963); 🔔 — по возрастанию ближайших наступлений (ММ-ДД); формат
  строк в обоих списках одинаковый — «Имя ГГГГ-ММ-ДД[ ЧЧ:ММ]».
- `node lunarreturns.js test "Костя 19630927"` — без регрессий.
