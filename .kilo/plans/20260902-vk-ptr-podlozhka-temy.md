# VK Mini App: Pull-to-Refresh, жёлтая подложка, светлая/тёмная тема

Файл для правок: `LunarReturns/index.html` (одна страница, инлайн CSS/JS).
Vendor `vendor/vk-bridge.min.js` (3.0.2) НЕ обновлять — это последний published
(latest в npm). `VKWebAppSetViewSettings` в схеме моста нет, но `send()` имя
события не валидирует — вызывать строкой с try/catch.

## 1. Подложка (чек-лист ВК: «цветная, не чёрная и не белая, видна при подтягивании»)

- `html { background: #f7d774 }` (цвет 🌙, светлый режим) — видна при
  bounce/overscroll вебвью и за краем при PTR.
- Тёмный режим: `html` фон `#7a6425` (тёмное золото, не чёрное) — см. п.3.
- `meta[name=theme-color]` оставить #f9f9f9 в светлом (это фон body PWA),
  в тёмном — менять скриптом на фон тёмного body.

## 2. Pull-to-Refresh (только VK-режим, без перечитывания облака ВК)

Режим: активен только при `vkminiapp` (index.html:237). В вебе ничего не менять.

Реализация (ванильные touch-события, без библиотек):
- `touchstart` (пассивный): запомнить startY; активен только если
  `scrollY === 0` и жест вниз.
- `touchmove` (`passive:false`): при `deltaY > 0 && scrollY === 0` —
  `preventDefault()`, сдвиг контента `document.body` через
  `transform: translateY(d/2 px)` (сопротивление 0.5), сверху под контентом
  показывается индикатор: 🌙 с CSS-вращением,opacity по прогрессу.
- Порог срабатывания ~70px: при `touchend` — если превышен, крутить 🌙
  ~600мс и сделать `location.reload()`; иначе — пружинный возврат
  (transition transform .2s).
- Обновление = перезагрузка страницы: цель — подтянуть свежую версию кода
  после деплоя (вебвью кеширует старую; PWA/SW в VK-режиме нет по README).
  Это закрывает пункт чек-листа «получить обновления, не выходя из
  приложения». Локальная база живёт в localStorage — не теряется;
  незакрытая форма редактирования теряется (штатная цена reload,
  жест осознанный). Облако ВК (VKWebAppStorage) по PTR НЕ перечитывать —
  решение владельца. Перед reload убрать сдвиг/индикатор, чтобы не было
  мигания (reload асинхронный, экран ещё виден).
- Прерывать жест при открытом `#pasteOverlay` (display:flex) — не активировать.
- Не трогать существующие click-обработчики строк списка (`#list .row`):
  отменять PTR-сдвиг по `touchcancel`.

## 3. Тёмная тема (авто, без ручного переключателя)

- Перевести цвета CSS на переменные в `:root`:
  `--bg #f9f9f9; --surface #fff; --border #ddd; --border2 #bbb;
  --btn #f0f0f0; --btn-h #e0e0f0(#e0e0e0); --text (default); --muted #555; --muted2 #777;
  --sel #e8f5e9; --err #c62828`.
- Тёмные значения по `@media (prefers-color-scheme: dark)`:
  `--bg #17171a; --surface #232327; --border #333338; --border2 #42424a;
  --btn #2c2c31; --btn-h #3a3a41; --muted #a0a0a8; --muted2 #8a8a92;
  --sel #274232; --err #ef9a9a`.
- Инлайновые цвета в HTML (`color:#555` и т.п.) заменить на `var(--…)`
  (инлайн-стили поддерживают var()). Затрагивает: статус-строку, ссылки
  «Сообщить об ошибке», подписи согласий, #pushlog, легенды.
- Приоритет источника темы в VK: launch-параметр `appearance` (или
  `vk_theme`) из `location.search` > `prefers-color-scheme`; в вебе — только
  медиазапрос. Реализация: если в VK-режиме параметр темный/светлый —
  добавить класс `theme-dark`/`theme-light` на `<html>`, перекрывающий
  медиазапрос (переменные объявить также на `.theme-dark`/`.theme-light`).
- Менять при старте `meta[name=theme-color]` (факт. фон body) и, в VK-режиме,
  вызвать `vkBridge.send("VKWebAppSetViewSettings", { status_bar_style,
  background_color })` с try/catch: фон = подложка (#f7d774 / #7a6425),
  `status_bar_style` = "light"/"dark" (тёмная тема — светлый текст статус-бара).
- QR-коды и 🌙-картинки остаются как есть (инверсия не требуется).
- Слушатель изменения темы (`matchMedia('(prefers-color-scheme: dark)')
  .addEventListener('change')`) — только обновить theme-color/SetViewSettings,
  CSS переменные подхватит медиазапрос сам.

## Тестирование (ручное)

   тёмная темы системы — жёлтая/тёмско-золотая подложка, 🌙 крутится,
   страница перезагружается (проверить выкат новой версии: после деплоя
   PTR подтягивает её без выхода из клиента ВК).
2. Скролл от середины списка — PTR не срабатывает, скролл обычный.
3. Диалог вставки (📋) открыт — PTR не мешает кнопкам.
4. m.vk.com и vk.com (веб): страница без PTR-логики, тёмная тема по системе.
5. Локально: `cd LunarReturns && npm run deploy` не требуется для проверки —
   открыть index.html напрямую; VK-специфику проверять в production-версии.

## Вне объёма (зафиксировано владельцем)

- Перезагрузка облака ВК (VKWebAppStorage) по PTR — не делать; PTR делает
  `location.reload()` (обновление версии кода), данные локальные.
- Ручной переключатель темы — не делать.
- user-select: none, offline-сообщения, execute-процедуры — отдельные задачи.
