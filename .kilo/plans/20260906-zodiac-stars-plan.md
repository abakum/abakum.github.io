# План: созвездие знака луны в полосе неба (LunarReturns)

## Цель

В тёмной теме в полосе неба `#ptrStars` рисовать яркими точками фигурку
текущего знака Зодиака, в котором сейчас луна, с подписью названия знака.
Фигурка — по центру по ширине; подпись — внизу полосы неба по высоте.

## Принятые решения (согласованы с пользователем)

1. «Созвездие» = знак Зодиака по `moonZodiacInt` (12 знаков по 30°, как в
   текстах приложения), НЕ реальные границы IAU (там 13–14 созвездий,
   луна часто в Змееносце).
2. Рисуем только точки (без линий-соединений) + подпись названия знака.
3. Размещение: по центру по ширине полосы; подпись у нижнего края полосы
   (высота полосы 280px).
4. Фоновые случайные звёзды — только правее и левее зодиака, по 25 штук
   с каждой стороны (итого 50 вместо нынешних 25 по всей ширине); на
   бокс фигурки они не попадают.
4. Видимость — как у неба: только тёмная тема (наследование `opacity` от
   `#ptrStars`); обёртка `#ptrWrap` с непрозрачным фоном перекрывает центр —
   фигурка видна при оттяжке PTR (главный сценарий) и на десктопе там, где
   видно небо. Пользователь принял это размещение осознанно.
5. Привязка к «сейчас» (дата на момент загрузки). Перерисовку при смене
   даты в приложении — вне объёма.

## Изменения (только `LunarReturns/index.html`)

### 1. Данные фигурок

Новый компактный массив из 12 записей `{ name, pts: [[x, y, sz], ...] }`:
`name` — русское название знака (строчными, как `MZODIAC_RU`), `pts` —
нормализованные координаты 0–1 внутри условного бокса ~140×140px + размер
точки. Фигурки стилизованные (узнаваемые схемы): Овен (4–5 точек), Телец
(V-образно), Близнецы (две фигурки), Рак (Y), Лев (серп), Дева (растянутая
Y), Весы (треугольник с перекладиной), Скорпион (длинная дуга с крючком),
Стрелец («чайник»), Козерог (широкий треугольник), Водолей (зигзаг),
Рыбы (две связки, соединённые V). Объём ~2–4 КБ, без внешних источников.

### 2. Отрисовка в существующем IIFE генерации звёзд (index.html:729-738)

Фоновые звёзды (переписать существующий цикл из 25 точек):

- Два одинаковых прохода по 25 звёзд: левая зона — от левого края до
  левой границы бокса зодиака, правая — от правой границы до правого
  края. Бокс фигурки ~140px по центру + зазор ~10px: левая зона
  `left: 0 … calc(50% - 80px)`, правая `calc(50% + 80px) … 100%`.
- Внутри зоны `left` — случайный %, `top` — случайный 0–250px, размеры
  1–2px как сейчас (`sz = i % 3 ? 2 : 1`).

Фигурка и подпись (добавить после фоновых звёзд):

- Знак считать инлайн: `Math.floor(moonNew(new Date()).longitude / 30) % 12`.
  **Важно:** `moonNew` — hoisted function declaration, доступна; а вот
  `norm360`/`MZODIAC_RU` (index.html:970-977) — `const` ниже по скрипту,
  обращение из этого IIFE упадёт по TDZ. Название знака брать из
  собственных данных п.1, формулу — дублировать (2 строки).
- Контейнер фигурки: абсолютный div внутри `starsBox`,
  `left: 50%; transform: translateX(-50%)`, бокс ~140×140px,
  вертикально по центру полосы (top ≈ 60px).
- Точки: те же `<i>`, что фоновые звёзды, но крупнее (2–3px против 1–2px),
  `opacity ~.95` — заметно ярче фоновых. Координаты `left: %; top: px`.
- Подпись: div с названием знака, `font-size ~10px`,
  `color rgba(255,255,255,.65)`, по центру, у нижнего края `starsBox`
  (bottom ≈ 8–12px полосы 280px).

### 3. CSS

Стили подписи/фигурки — в существующий блок `#ptrStars` (index.html:286-296):
можно минимально — инлайн-стили в JS + один класс для подписи в `<style>`.
Ничего в правилах `#ptrWrap`/`#ptrMoon` не менять.

## Подводные камни

- TDZ `norm360`/`MZODIAC_*` — см. п.2 (главная ловушка).
- На узких экранах (портрет ≤ ~200px между краем и боксом) боковые зоны
  сужаются — это норма: звёзды там и так видны только в полях/при оттяжке.
- Фигурка по центру перекрыта обёрткой в статике — видна при оттяжке PTR:
  согласовано, менять положение не нужно.
- `#ptrStars` имеет `opacity: 0` вне тёмной темы — подпись и точки
  скрываются автоматически, отдельной логики темы не нужно.

## Проверка

1. `https://abakum.github.io/LunarReturns/?vk_app_id=1&ptr=100` (окно
   600×1200): при оттяжке видна фигурка по центру и подпись внизу неба,
   фоновые звёзды — только слева и справа от фигурки (по 25 на сторону);
   `?appearance=dark` — то же в тёмной теме.
2. Светлая тема (`&appearance=light`) — фигурки, подписи и звёзды не видно.
3. Сверить знак на фигурке с текстом в приложении («луна в …») — должны
   совпадать (одна долгота из `moonNew`).
4. Без параметра `ptr` регрессий нет: фоновые звёзды в полях как раньше.
5. Десктоп 1920×1080, тёмная тема: фигурка по центру видна там, где небо
   не перекрыто (в двух колонках обёртка почти на всю ширину — видна при
   оттяжке; это ожидаемо).
6. `npm run build` не запускать (запрещено AGENTS.md, сборку делает
   workflow деплоя).

# Отчёт о реализации (06.09.2026)

Реализовано в `LunarReturns/index.html`; в ходе работы план уточнялся
запросами пользователя — ниже состояние «как построено».

## Что сделано

1. **Данные фигурок** — `ZODIAC_FIGS` внутри `drawZodiac()`: 12 знаков,
   у каждого `name` (строчное русское название) + `pts` (нормализованные
   координаты точек 0–1, размер 1–3px) + `seg` (пары индексов `pts` для
   линий-соединений; добавлены по запросу после первичной версии
   «только точки»).
2. **Фоновые звёзды** — 50 вместо 25: по 25 левее и правее бокса зодиака,
   координата края `calc((100% - 160px) * rand)` (бокс 140px + зазор),
   создаются при загрузке, без ожидания тяги.
3. **Ленивая отрисовка фигурки** — `drawZodiac()` с флагом
   `zodiacDrawn` (один раз за загрузку). Вызовы: при старте тяги PTR
   (в `touchmove` рядом с `ptr-moon`) и сразу при `?ptr=N > 0`
   (скриншоты headless). Знак считается инлайн
   `Math.floor(moonNew(new Date()).longitude / 30) % 12` — `moonNew`
   доступна как hoisted declaration, а `norm360`/`MZODIAC_*` (const ниже
   по скрипту) не трогаются из-за TDZ.
4. **Отрисовка**: в боксе `.ptr-zodiac` сначала SVG (`viewBox 0 0 140 140`)
   с тонкими линиями `rgba(255,255,255,.35)`, поверх — точки-`<i>`
   (наследуют `#ptrStars i`), ярче фоновых (`opacity .95`).
5. **Размещение** (уточнено пользователем): бокс 140×140 у **верхнего
   края** полосы неба (`top: 8px`, центр по ширине); подпись названия
   знака — **сразу под боксом** (`top: 152px`, центрирована).
6. **Луна-эмодзи фазы** (доп. запрос): `#ptrMoon` — теперь `<div>` с
   юникодом фазы по титхи (`phaseName(tithiInt(moonNew(new Date())), false)`),
   вместо статичной `1f319.webp`. Размер 80px, стоит **слева** от бокса
   зодиака (`left: calc(50% - 218px)`, `top: 38px` — по центру бокса);
   правило `.two-col` удалено — привязка к колонке не нужна. Иконка в
   заголовке `#titleH1` осталась прежней картинкой, `renderTitle()` не
   менялся.
7. **Ранний сдвиг `?ptr=N`** (из соседнего плана
   `20260906-screenshots-ptr-plan.md`, реализован ранее тем же днём):
   скрипт в `<head>` до первого кадра ставит `--ptrShift` и класс
   `ptr-moon`; `#ptrWrap` — `transform: translateY(var(--ptrShift, 0px))`.

## Ключевые строки (после всех правок)

- CSS: `#ptrMoon` ~263–277, `.ptr-zodiac*` ~297–319.
- JS: фоновые звёзды ~745–756, `drawZodiac` + вызовы ~758–827.
- Установка эмодзи фазы в `#ptrMoon`: после `const tithiName` ~1053–1058.
- Ранний скрипт `?ptr=N`: `<head>` ~95–102.

## Проверки

- Синтаксис всех 4 инлайн-скриптов (`new Function`) — OK.
- Маппинг 30 титхи → 8 фаз-эмодзи корректен и монотонен
  (06.09.2026 → 🌘); знаки по `moonNew`: 06.09.2026 → рак (индекс 3),
  01.01.2026 → близнецы, 30.03.2026 → дева.
- Данные фигурок: все индексы `seg` в пределах `pts`, координаты 0–1,
  12 фигурок — ошибок нет.
- Визуальная проверка оттяжки (`?ptr=100`, тёмная/светлая тема) — за

  5–6 с `ptr=100` при 1920×1080); `npm run build` не запускался
  (запрещено AGENTS.md).

## Отклонения от исходного плана

- Добавлены линии (`seg` + SVG) — изначально планировались «только точки».
- Фигурка ленивая (рисуется при старте PTR / `?ptr=N`), а не при загрузке.
- Бокс сверху полосы, подпись под боксом (план: центр полосы / подпись
  внизу полосы).
- Бонусом: луна в небе — юникод фазы по титхи 80px слева от бокса вместо
  статичной картинки.
