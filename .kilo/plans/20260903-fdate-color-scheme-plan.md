# План: фикс плейсхолдера fDate (продолжение color-scheme)

**Дата:** 2026-09-03
**Файл:** `LunarReturns/index.html`
**Предыстория:** JS-хак цвета fDate заменён на CSS `color-scheme` (готово). Регрессия: плейсхолдер пустого `input[type=date]` теперь неконтрастен — белый на белом в светлой теме, чёрный на чёрном в тёмной. Значения в fDate/fCity/fHour контрастны; плейсхолдеры fCity/fHour контрастны.

## Диагноз

Chromium/WebView рисует плейсхолдер пустого дейт-инпута внутренними UA-стилями, привязанными к эффективному `color-scheme` (механизм `light-dark()`), и **игнорирует** CSS `color` элемента. Когда схема, по которой красит UA, расходится с CSS-переменными страницы (типично для Android WebView в нативном клиенте VK), плейсхолдер инвертируется. fCity/fHour не затронуты: их «плейсхолдер» — обычный option/текст, красящийся от `color: var(--muted)`.

## Почему не «как с fCity»

Приём fCity (inline `sel.style.color = ... : "var(--muted)"`, index.html:886) работает, потому что плейсхолдер селекта — обычный `<option>`-текст. Плейсхолдер дейт-инпута рисует нативный код WebView, CSS `color` (и inline) он игнорирует — удалённый JS-хак именно поэтому красил значения, но не плейсхолдер. `::-webkit-datetime-edit` — единственный способ задать цвет этого текста в Chromium/WebView.

## Изменение (одно, CSS-only)

В блок стилей контролов (~строка 94–101) добавить Chromium-псевдоэлемент, который красит и сегменты даты, и плейсхолдер пустого поля:

```css
input[type="date"]::-webkit-datetime-edit { color: var(--muted); }
```

Правило ставится сразу после общего блока `input...select, textarea`. Оно перекрывает UA-инверсию, беря цвет из той же переменной, что и у соседних контролов — оба состояния (плейсхолдер и значение) согласованы и не зависят от расхождения color-scheme. Цвет значений не изменится (уже `var(--muted)`).

Опционально (в тёмной теме значок календаря может остаться тёмным): `input[type="date"]::-webkit-calendar-picker-indicator { filter: invert(1); }` — только если визуально нужен; проверить перед добавлением.

## Риски

- `::-webkit-datetime-edit` — не стандарт, но поддержан во всех Chromium (включая Android WebView) с 2013; Firefox/Safari его игнорируют — там продолжает работать `color-scheme`. Деградации нет.
- Правило действует и на заполненное поле — цвет совпадает с текущим (`--muted`), изменений не видно.

## Валидация

- Светлая тема: пустой fDate — плейсхолдер «дд.мм.гггг» серый (#555) на белом; заполненный — читаем.
- Тёмная тема: то же с #a0a0a8 на #232327.
- Принудительная тема VK, отличная от системной (`.theme-dark`/`.theme-light`), — плейсхолдер контрастен в обоих направлениях.
- fCity/fHour — без изменений.
- Браузер desktop + нативный клиент VK (Android).
