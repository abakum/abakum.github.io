# План: фикс плейсхолдера fDate — HTML-оверлей над пустым полем

**Дата:** 2026-09-03 (ревизия 7 — финальная; оверлей р.1–3 закоммичен в `a72100a`; р.4–5 — showPicker на touch и скрытие оверлея при фокусе — реализованы, лежат незакоммиченными вместе с этим планом)
**Решение (финал):** оверлей — единственное надёжное решение; эксперименты с элементным `color-scheme` / meta color-scheme отклонены (подсказка UA без гарантий, случай «тема VK ≠ схема WebView» не решают). Новых правок кода план не требует — осталось закоммитить уже реализованные р.4–5 и проверить на устройстве по чек-листу ниже.
**Дополнение (р.4):** на Android в дейт-пикере нельзя вводить день/месяц цифрами, поэтому при провале валидации пустого fDate (`submitRecord`, index.html:832) мало `fDateEl.focus()` — нужно открыть календарь через `showPicker()`. Только на touch (гейт тем же matchMedia `(hover: none) and (pointer: coarse)`), десктоп не трогаем: там дату можно набрать с клавиатуры.

**Дополнение (р.5):** при фокусе на fDate (в т.ч. при открытом пикере) оверлей надо прятать — иначе «Дата» висит над пустым полем во время выбора. Чисто CSS: `#dateWrap:focus-within #fDatePh { display: none; }` внутри touch-медиаблока; при blur без выбора даты оверлей возвращается сам (класс `filled` не установлен).

**Дополнение (р.8):** «Дата» выглядит ярче «Имя»: у fName нет стилизации `::placeholder`, Chromium рисует его UA-стилем — цвет поля `var(--muted)` с прозрачностью ~54%; оверлей же красится чистым `var(--muted)`. Привести оверлей к виду нативного плейсхолдера: добавить в правило `#fDatePh` внутри touch-медиаблока `opacity: .54;` (фон оверлея совпадает с `--surface` под ним — его притемнение не видно; размер шрифта одинаков — оба `font: inherit`).

## Изменение

1. `submitRecord`, строка 832: заменить `else fDateEl.focus();` на:

```js
else {
    fDateEl.focus();
    if (fDateEl.showPicker && matchMedia("(hover: none) and (pointer: coarse)").matches) {
        try { fDateEl.showPicker().catch(() => {}); } catch (e) {}
    }
}
```

2. CSS, внутри существующего `@media (hover: none) and (pointer: coarse)` (index.html:113–126), добавить строку:

```css
#dateWrap:focus-within #fDatePh { display: none; }
```

3. Там же, в правило `#fDatePh`, добавить `opacity: .54;` (р.8 — вид как у нативного плейсхолдера fName).

- `showPicker()` допустим только при user activation — обработчик submit вызывается по клику/Enter, активация есть; `.catch`/`try` — защитa от сред, где API нет или оно кидает (iOS Safari: `showPicker` отсутствует — фокус остаётся как сейчас).
- Инпут всегда видим (оверлей с `pointer-events: none`), фокус и пикер срабатывают без дополнительных трюков с display.

## Валидация

1. Android WebView (VK): отправка формы с пустой датой → сообщение «Укажите имя и дату события» + раскрывается нативный календарь, оверлей «Дата» скрыт; выбор даты → поле заполнено, оверлея нет; закрытие пикера без выбора → оверлей вернулся.
2. Ручной тап в пустое fDate → оверлей скрыт на время фокуса, blur без выбора → вернулся.
3. Десктоп: поведение прежнее — фокус в поле, дата набирается вручную, календарь не раскрывается принудительно.
4. Touch: пустые fName и fDate рядом — «Имя» и «Дата» одинаково тусклые (цвет ~54% от `--muted`), одинаковый размер шрифта.

## Исследование (почему оверлей — единственное надёжное решение, р.6)

Хронология по git подтверждает: до коммита `92afb4f` плейсхолдер был чёрным (UA-стили схемы light по умолчанию — `color-scheme` не объявлялся), т.е. терял контраст только в тёмной теме. После объявления `color-scheme` в блоках тем расхождение «эффективная схема WebView ↔ классы страницы» стало инвертировать плейсхолдер в обе стороны — light-кейс появился тогда же. Условие расхождения нестабильно (зависит от настроек клиента), поэтому гейтинг оверлея по теме не надёжен — только по touch.

Управление нативным цветом исчерпано: `color` (inline JS) — игнорируется; `::-webkit-datetime-edit { color }` (`eb4237a`) — проверено, не сработало; root/элементный `color-scheme` — подсказка UA без гарантий. Прочитать фактически нарисованный цвет скриптом нельзя: `getComputedStyle` (в т.ч. по псевдоэлементу) возвращает заявленные CSS-значения, использованная UA-схема не экспонируется, а нативно нарисованный контрол в canvas не отрисовать. Вывод: единственное детерминированное решение — рисовать плейсхолдер средствами страницы (текущий оверлей).

**Статус предыдущей попытки:** CSS-правило `input[type="date"]::-webkit-datetime-edit { color: var(--muted); }` (index.html:110) применено, но в целевой среде (Android WebView ВК) плейсхолдер пустого дейт-инпута всё ещё белый-на-белом / чёрный-на-чёрном — нативный слой рисует его мимо CSS-псевдоэлементов. Идея «прозрачный фон» отклонена: под инпутом та же `--surface` секции (жёлтая подложка `html` перекрыта непрозрачным `background: var(--bg)` у `body`), и цвет нативного текста от фона инпута не зависит.

**Уточнение (р.3):** на десктопе плейсхолдер виден и контрастен в обеих темах — оверлей нужен только для мобильных (touch). Включение оверлея гейтится CSS-медиазапросом `@media (hover: none) and (pointer: coarse)` — на десктопе оверлей скрыт, работает нативный плейсхолдер; JS остаётся общий (класс `filled` на десктопе просто ни на что не влияет).

## Решение (реализовано, р.1–3; раздел ниже — для истории)

Убрать зависимость от нативного плейсхолдера: поверх пустого `#fDate` рисуется обычный `<span>` «дд.мм.гггг» цветом `var(--muted)` — это HTML-текст, крашится движком страницы, платформенно-независимо. Инпут всегда остаётся видимым и кликабельным (у оверлея `pointer-events: none`), нативный пикер открывается как обычно. Оверлей имеет непрозрачный фон `var(--surface)` — заодно закрывает неконтрастный нативный текст, если он виден. Правило `::-webkit-datetime-edit` (строка 110) оставить — в desktop Chrome оно красит сегменты даты корректно.

## Изменения

1. **HTML (строка 182):** обернуть инпут в контейнер и добавить оверлей:

```html
<span id="dateWrap" style="position:relative;">
    <input type="date" id="fDate" style="width:9em;" title="Дата — по времени места события">
    <span id="fDatePh" aria-hidden="true">Дата</span>
</span>
```

Текст оверлея — статичная подпись «Дата» (по образцу `placeholder="Имя"` у fName); вычисление формата под локаль (`datePlaceholderLabel()` из коммита 33e6572) не переносим — формат даты покажет нативный пикер.

2. **CSS (после блока контролов, ~строка 105):**

```css
#fDatePh { display: none; } /* десктоп: работает нативный плейсхолдер */
@media (hover: none) and (pointer: coarse) { /* только touch-устройства */
    #fDatePh {
        position: absolute; inset: 0;
        display: flex; align-items: center;
        padding: 0 6px;              /* как padding инпутов */
        background: var(--surface);  /* непрозрачно: прячет нативный текст */
        color: var(--muted);
        pointer-events: none;
    }
    #dateWrap.filled #fDatePh { display: none; }
}
```

3. **JS (рядом с `const fDateEl` ~строка 925):**

```js
function syncDatePh() {
    document.getElementById("dateWrap").classList.toggle("filled", !!fDateEl.value);
}
["input", "change"].forEach(ev => fDateEl.addEventListener(ev, syncDatePh));
syncDatePh();
```

4. **JS — программные установки value** (события `input`/`change` при них не падают):
   - `submitRecord` после строки 857;
   - `startEdit` после строки 868;
   - `cancelEdit` после строки 884;
   
   добавить вызов `syncDatePh();`.

## Риски

- Гейтинг по `(hover: none) and (pointer: coarse)`: гибриды с тач-экраном, но мышью как основным указателем, получат десктоп-режим (нативный плейсхолдер, который там корректен) — это безопасное поведение по умолчанию.
- Двойной текст, если нативный плейсхолдер всё же видим: закрыт непрозрачным фоном оверлея.
- Рассинхрон при установке value из мест вне списка — grep `fDate").value =` покрывает все три сайта (857, 868, 884).
- `inset` поддержан Chromium 87+ (2020); при нужде заменить на явные `top/right/bottom/left: 0`.

## Валидация (реализованной части)

1. Desktop Chrome (pointer: fine), светлая/тёмная тема: пустое fDate — нативный плейсхолдер, оверлей скрыт (`#fDatePh` display:none); поведение как до изменения.
2. DevTools mobile emulation или Android WebView, обе темы, включая принудительную тему VK, отличную от системной: пустое fDate — надпись «Дата» цвета `--muted`, контрастна; тап — открывается пикер; выбор даты — оверлей скрыт; очистка — вернулся.
3. Цикл редактирования: `startEdit` → инпут заполнен, оверлея нет; сохранение/отмена → поле пусто, оверлей виден.
4. fCity/fHour/fName — без изменений.
