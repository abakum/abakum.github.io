# План: убрать JS-хак цвета fDate через CSS color-scheme

**Дата:** 2026-09-03
**Файл:** `LunarReturns/index.html`

## Задача

Инлайн-задание цвета `#fDate` в `applyTheme()` (строки ~318–322) — хардкод hex, дублирующий `--muted` из CSS. Заменить стандартным механизмом `color-scheme`, который заставляет браузер рендерить нативные контролы (`input[type=date]`, `select`, скроллбары) в теме страницы.

## Изменения

1. **CSS: добавить `color-scheme` в три блока переменных:**
   - `:root { ... }` (~строка 15): добавить `color-scheme: light;`
   - `:root.theme-light { ... }` (~строка 28): добавить `color-scheme: light;`
   - Тёмные блоки `@media (prefers-color-scheme: dark) { :root:not(.theme-light) {...} }` (~строка 30) и `:root.theme-dark {...}` (~строка 44): добавить `color-scheme: dark;`
   - Не заводить новую переменную — просто по одному свойству в каждый блок.

2. **JS: удалить хак из `applyTheme()`** — строки с комментарием про Android WebView и `fDateEl.style.color = ...` (~318–322).

3. **Проверить `#fDate`/`#fCity` на читаемость:** после удаления инлайна цвет текста дейт-инпута определяется нативным рендером по `color-scheme`. Если нужен приглушённый (как было `--muted`), добавить CSS-правило (не JS):
   ```css
   #fDate { color: var(--muted); }
   ```
   Это работает в браузерах, где дейт-инпут уважает CSS color; там где рисует нативно (Android), `color-scheme` гарантирует правильную тему.

## Риски

- Старые WebView без поддержки `color-scheme` (Chrome 81+, 2020) вернутся к прежнему поведению — чёрный текст в тёмной теме на Android. Целевые клиенты ВК используют свежий System WebView — приемлемо.
- `color-scheme` также меняет вид нативных скроллбаров и дефолтных фонов контролов — визуально проверить светлую тему (не должно стать темнее).

## Валидация

- Браузер: переключить системную тему — `input[type=date]`, `select`, фон контролов в правильной теме; инлайн `style` у `#fDate` пуст.
- VK нативный клиент (по возможности): то же в обеих темах ВК.
- Тёмная тема: текст даты читаем на `--surface` (#232327).
- Проверить, что принудительная тема (`.theme-dark` при светлой системе) тоже красит контролы — `color-scheme` в блоках классов это покрывает.
