# План: фикс плейсхолдера fDate — HTML-оверлей над пустым полем

**Дата:** 2026-09-03 (ревизия 3)
**Файл:** `LunarReturns/index.html`
**Статус предыдущей попытки:** CSS-правило `input[type="date"]::-webkit-datetime-edit { color: var(--muted); }` (index.html:110) применено, но в целевой среде (Android WebView ВК) плейсхолдер пустого дейт-инпута всё ещё белый-на-белом / чёрный-на-чёрном — нативный слой рисует его мимо CSS-псевдоэлементов. Идея «прозрачный фон» отклонена: под инпутом та же `--surface` секции (жёлтая подложка `html` перекрыта непрозрачным `background: var(--bg)` у `body`), и цвет нативного текста от фона инпута не зависит.

**Уточнение (р.3):** на десктопе плейсхолдер виден и контрастен в обеих темах — оверлей нужен только для мобильных (touch). Включение оверлея гейтится CSS-медиазапросом `@media (hover: none) and (pointer: coarse)` — на десктопе оверлей скрыт, работает нативный плейсхолдер; JS остаётся общий (класс `filled` на десктопе просто ни на что не влияет).

## Решение

Убрать зависимость от нативного плейсхолдера: поверх пустого `#fDate` рисуется обычный `<span>` «дд.мм.гггг» цветом `var(--muted)` — это HTML-текст, крашится движком страницы, платформенно-независимо. Инпут всегда остаётся видимым и кликабельным (у оверлея `pointer-events: none`), нативный пикер открывается как обычно. Оверлей имеет непрозрачный фон `var(--surface)` — заодно закрывает неконтрастный нативный текст, если он виден. Правило `::-webkit-datetime-edit` (строка 110) оставить — в desktop Chrome оно красит сегменты даты корректно.

## Изменения

1. **HTML (строка 182):** обернуть инпут в контейнер и добавить оверлей:

```html
<span id="dateWrap" style="position:relative;">
    <input type="date" id="fDate" style="width:9em;" title="Дата — по времени места события">
    <span id="fDatePh" aria-hidden="true">Дата</span>
</span>
```

Текст оверлея — статичная подпись «Дата» (по образцу `placeholder="Имя"` у fName); вычисление формата под локаль (`datePlaceholderLabel()` из коммита 33e6572) не переносим — формат даты покажет нативный пикер.

2. **CSS (после блока контролов, ~строка 105):**

```css
#fDatePh { display: none; } /* десктоп: работает нативный плейсхолдер */
@media (hover: none) and (pointer: coarse) { /* только touch-устройства */
    #fDatePh {
        position: absolute; inset: 0;
        display: flex; align-items: center;
        padding: 0 6px;              /* как padding инпутов */
        background: var(--surface);  /* непрозрачно: прячет нативный текст */
        color: var(--muted);
        pointer-events: none;
    }
    #dateWrap.filled #fDatePh { display: none; }
}
```

3. **JS (рядом с `const fDateEl` ~строка 925):**

```js
function syncDatePh() {
    document.getElementById("dateWrap").classList.toggle("filled", !!fDateEl.value);
}
["input", "change"].forEach(ev => fDateEl.addEventListener(ev, syncDatePh));
syncDatePh();
```

4. **JS — программные установки value** (события `input`/`change` при них не падают):
   - `submitRecord` после строки 857;
   - `startEdit` после строки 868;
   - `cancelEdit` после строки 884;
   
   добавить вызов `syncDatePh();`.

## Риски

- Гейтинг по `(hover: none) and (pointer: coarse)`: гибриды с тач-экраном, но мышью как основным указателем, получат десктоп-режим (нативный плейсхолдер, который там корректен) — это безопасное поведение по умолчанию.
- Двойной текст, если нативный плейсхолдер всё же видим: закрыт непрозрачным фоном оверлея.
- Рассинхрон при установке value из мест вне списка — grep `fDate").value =` покрывает все три сайта (857, 868, 884).
- `inset` поддержан Chromium 87+ (2020); при нужде заменить на явные `top/right/bottom/left: 0`.

## Валидация

1. Desktop Chrome (pointer: fine), светлая/тёмная тема: пустое fDate — нативный плейсхолдер, оверлей скрыт (`#fDatePh` display:none); поведение как до изменения.
2. DevTools mobile emulation или Android WebView, обе темы, включая принудительную тему VK, отличную от системной: пустое fDate — надпись «Дата» цвета `--muted`, контрастна; тап — открывается пикер; выбор даты — оверлей скрыт; очистка — вернулся.
3. Цикл редактирования: `startEdit` → инпут заполнен, оверлея нет; сохранение/отмена → поле пусто, оверлей виден.
4. fCity/fHour/fName — без изменений.
