# План: плейсхолдер fDate — замена нативного на кнопку-заглушку

**Дата:** 2026-09-03
**Файл:** `LunarReturns/index.html`, `LunarReturns/sw.js`
**Предыстория:** Фикс `::-webkit-datetime-edit { color: var(--muted) }` (коммит eb4237a) работает на десктопе (подтверждено headless-Chrome по пикселям: и пустой, и заполненный инпут красятся в `--muted`), но на Android не работает нигде — ни в Chrome, ни в PWA, ни в вебвью VK. Вывод: на Android Chromium рисует «дд.мм.гггг» пустого дейт-инпута нативным кодом в обход всех доступных CSS-псевдоэлементов. Достать его CSS-ом нельзя.

## Решение

Убрать зависимость от нативного плейсхолдера: когда `fDate` пуст — показывать вместо инпута обычный `<button type="button">` с текстом «дд.мм.гггг» (стилизован под инпут, цвет `var(--muted)` — рисуется самим движком как обычный текст, платформенно-независимо). По тапу — вернуть инпут и открыть нативный пикер через `showPicker()`.

Заполненное состояние не меняется вообще: нативный рендер значения контрастен на всех платформах (подтверждено ранее).

## Изменения

### 1. HTML (~строка 178)

Внутри `<span>` с фильтрами, перед `input#fDate`:

```html
<button type="button" id="fDateBtn" style="width:9em;display:none;" title="Дата — по времени места рождения">дд.мм.гггг</button>
```

Обязательно `type="button"` — кнопка внутри `<form>`, иначе submit.

### 2. CSS (блок контролов, ~строка 94–106)

- Добавить `#fDateBtn` в селектор-список стилей инпутов (`input[type="text"], ..., #fDateBtn { ... }`) — рамка, фон `var(--surface)`, цвет `var(--muted)`, `font: inherit`. Курсор — `pointer` уже есть для `button`? Нет, у button в этом файле свой блок (строка ~85–93): проще дать `#fDateBtn` те же стили, что инпутам, отдельной строкой в существующем селекторе.
- Правило `input[type="date"]::-webkit-datetime-edit` (строка 106) оставить — красит сегменты заполненного поля на десктопе.

### 3. JS

```js
const fDateEl = document.getElementById("fDate");
const fDateBtn = document.getElementById("fDateBtn");

function syncDateBtn() {
    const empty = !fDateEl.value;
    fDateBtn.style.display = empty ? "" : "none";
    fDateEl.style.display = empty ? "none" : "";
}

fDateBtn.addEventListener("click", () => {
    syncDateBtn();                       // показать инпут (для showPicker он должен быть отрендерен)
    fDateEl.focus();
    if (fDateEl.showPicker) fDateEl.showPicker().catch(() => {});
    // showPicker может бросить «not rendered» при смене display в том же тике —
    // при необходимости обернуть в requestAnimationFrame(() => fDateEl.showPicker()...)
});
["input", "change"].forEach(ev => fDateEl.addEventListener(ev, syncDateBtn));
```

- Начальный вызов `syncDateBtn()` при старте (fDate изначально пуст → кнопка видна).
- Явные вызовы `syncDateBtn()` после каждой программной установки `fDate.value`:
  - `submitRecord()` — строка 829 (очистка после добавления);
  - `startEdit()` — строка 840;
  - `cancelEdit()`/`deleteCurrent()` — строки 856 и, если чистят fDate, тоже (проверить ~850–870).
  Программное присваивание `value` событий `input`/`change` не генерирует.

### 4. sw.js

`CACHE = "lunarreturns-v9"` → `"v10"` — чтобы PWA переустановила закэшированный index.html (INSTALL_URLS включает `./index.html`).

### 5. Деплой

- Commit + push (GitHub Pages обновится сам).
- VK-мини-апп деплоится вручную: `cd LunarReturns && npm run deploy` — вероятно, фикс eb4237a в VK вообще не доезжал (деплой не выполнялся), это надо сделать и для нового кода.

## Риски и граничные случаи

- `showPicker()` недоступен (старый WebView/iOS Safari) — catch: инпут просто показывается, пользователь открывает пикер тапом по полю, как раньше. Деградации нет.
- Очистка даты из нативного пикера («Очистить» на Android) → событие `input`/`change` с пустым значением → кнопка возвращается.
- Кнопка в tab-порядке вместо скрытого инпута; Enter/Space открывают пикер — a11y не хуже.
- Пустое поле в `submitRecord` проверяется по `fDate.value` (строка 781) — инпут с `display:none` всё ещё в DOM, значение читается. Скрытие инпута пустого поля не ломает валидацию «Укажите дату».
- Десктоп: визуально пустое поле выглядит как раньше (кнопка, стилизованная под инпут, с тем же текстом «дд.мм.гггг»); клик сразу открывает календарь (`showPicker` в десктопном Chrome ≥99).

## Валидация

1. Десктоп Chrome, светлая/тёмная: пустое fDate — «дд.мм.гггг» цвета `--muted`, контрастен; клик — открывается календарь; выбор даты — поле заполнено, кнопка скрыта; «Очистить»/удаление записи — кнопка возвращается.
2. Android Chrome + PWA: то же самое, обе темы системы.
3. VK-мини-апп после `npm run deploy`: то же, включая принудительную тему VK, отличную от системной.
4. Цикл редактирования: выбор записи из списка (startEdit) → fDate заполнен, инпут виден; отмена/сохранение → пуст, кнопка видна.
5. PWA после обновления: `swver` показывает `v10`.
